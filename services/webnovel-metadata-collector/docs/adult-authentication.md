# 19세 작품 인증 수집 기록

이 문서는 19세 작품 검색에서 실제로 발생한 증상, 확인한 원인, 적용한 해결 방법과 대표 검증 작품을 누적한다. 새 인증 장애를 수정할 때 같은 형식으로 추가한다.

소설 뷰어가 인증 브라우저와 검색 API를 호출하는 방법 및 응답 판정 규칙은 [소설 뷰어용 19세 인증 API 연동](viewer-auth-integration.md)을 참고한다.

## 동작 범위

- 인증 검색은 기본값이 꺼진 선택 기능이다.
- 리디·카카오페이지는 로그인 없이 공개 HTTP API에서 표지·메타데이터를 조회한다. 두 플랫폼의 `사용` 설정과
  `19세 검색 결과 포함`을 모두 켜야 성인 후보를 조회한다. 작품 본문을 내려받는 기능은 아니다.
- 네이버 시리즈는 사용자가 프로그램 전용 Chrome/Edge 창에서 직접 로그인과 성인 인증을 완료한 세션을 사용한다.
- 노벨피아는 이메일 계정으로 발급한 `LOGINKEY` 또는 사용자가 입력한 소셜 계정 `LOGINKEY`를 사용한다. 이메일과
  비밀번호는 사용자가 허용한 self-host 수집기 private volume에 저장해 만료 시 자동 로그인한다.
- 로그인·성인 인증·CAPTCHA를 우회하지 않는다.
- 기본 브라우저 프로필과 인증 쿠키를 가져오지 않는다.
- 인증 검색을 켠 플랫폼의 19세 후보를 공개 검색과 함께 비교해 최종 작품 한 건만 반환한다.
- 인증 검색에서 확인한 19세 후보와 최종 메타데이터에는 공통 `19금` 태그를 추가한다.

## 공통 인증 흐름

리디·카카오페이지는 `사용`만 선택한다. 네이버 시리즈는 `로그인 창 열기` → 전용 브라우저 로그인/성인 인증 → `로그인 완료·사용` 순서로 연결한다.
노벨피아는 이메일·비밀번호 또는 소셜 계정의 `LOGINKEY`를 입력하고, 서버가 실제 성인 모드 요청을 확인한 뒤
연결한다. 이후 공통으로 `검색할 때 19세 작품 포함`을 켜고 검색한다.

## 익명 메타데이터 실측 및 구현 판단 (2026-09-10)

새 HTTP 클라이언트로 기존 extractor의 검색·상세·표지 요청만 실행했다. 저장된 로그인 프로필, 계정 비밀이나
회차 본문은 사용하지 않았다. 아래 결과는 이 개발 PC에서의 관측이며 self-host 서버 IP와 모든 작품에 대한 보장은 아니다.

| 플랫폼 | 관측 | 다음 구현 |
| --- | --- | --- |
| 리디 | `상수리나무 아래` 검색에서 성인 연재 ID `1922000007` 반환 | 기존 직접 검색을 `public_adult`로 선언하고 UI/서버의 로그인·Playwright 요구 제거 |
| 카카오페이지 | `앵무새 프로젝트 [19세 완전판]` (`61800468`), `절대우위 [19세 완전판]` (`64870198`) 모두 익명 검색·상세 성공. 작가·소개·표지 URL 존재, 표지 GET은 JPEG/HTTP 200 | 두 작품으로 공개 메타데이터 회귀를 만들고 기존 BFF 직접 HTTP 경로를 성인 검색에도 사용. 실패 시 인증 필요/접속 실패를 구분 |
| 네이버 시리즈 | `네이키드 베이비` 검색에 성인 ID `14445233`, `12513961`이 있지만 파싱된 표지·소개는 없음. `14445233` 상세는 로그인 페이지로 redirect | 실제 시리즈 세션이 필요한 우선 대상. 쿠키 묶음 또는 기존 전용 프로필의 유효성을 상세 응답으로 검증 |

따라서 아래 9월 9일의 **카카오페이지는 먼저 인증 필드를 실측해야 한다**는 우선순위를 수정한다. 현재 목표는
표지·메타데이터이므로 우선 공개 HTTP 경로로 충족할 수 있는 범위를 구현하고, 인증이 필요한 작품에서만 세션 방식을
검토한다. 카카오페이지 웹 화면에서 로그인 안내가 보인다는 사실만으로 메타데이터 API도 인증이 필요하다고 판단하지 않는다.

시리즈의 `NID_AUT`/`NID_SES` 두 값만으로 현재 상세·표지 조회가 되는지는 로그인된 실제 계정으로 아직 검증하지 않았다.
브라우저에서 로그인된 것, 수집기가 프로필을 저장한 것, 성인 작품 상세를 읽을 수 있는 것은 별도 상태다. 현행
`finish_login()`은 브라우저 저장/재개를 확인할 뿐 시리즈의 로그인·성인 인증 probe를 수행하지 않으므로 보완해야 한다.

일반 Moya 웹 페이지는 다른 사이트의 로그인 쿠키를 직접 읽을 수 없다. 수동 쿠키 입력은 선택적 대체 경로로 두고,
기존 원격 로그인이나 향후 PC 연결 도구가 세션 저장을 처리하는 것이 모바일 사용성에 적합하다. 공통 인증 선언·저장
경계를 재사용하며 별도 인증 서버나 대규모 플랫폼 재설계가 선행될 필요는 없다. 실제 세션 만료 후 자동 갱신 가능성은
사이트별로 확인하며 노벨피아와 같은 아이디/비밀번호 자동 재로그인을 보장하지 않는다.

## 2026-09-10 공개 성인 메타데이터 구현

- `/health`의 `adult_auth.public_search_platforms`에 `kakao_page`, `ridi`를 추가했다. Moya는 이 선언이 있는
  플랫폼에 로그인 버튼 대신 `사용` 체크박스를 표시한다. 구형 수집기가 선언하지 않으면 기존 UI를 유지한다.
- 공개 플랫폼 활성화는 서버의 기존 플랫폼 선택 저장만 수행한다. 다른 플랫폼의 진행 중인 로그인을 종료하거나
  저장하지 않으며 Playwright 없이도 동작한다. 전역 성인 검색 옵션은 자동으로 켜지지 않는다.
- 카카오페이지 성인 검색과 상세는 일반 HTTP 클라이언트를 사용한다. 리디의 기존 직접 HTTP 검색도 같은 설정
  흐름으로 연결했다. 공개 경로 오류는 로그인 오류로 표시하지 않는다.
- 공개 성인 후보가 최종 선택됐으면 응답의 `public_adult_metadata: true`로 표시한다. `authenticated_search`를
  로그인 성공처럼 꾸미지 않는다. Moya 자동 적용은 이 별도 근거를 인정하면서 정확한 제목·작가 및 완전한 정보
  조건을 계속 검사한다. 구형 응답에서 필드가 없으면 기존 보수적인 판정을 유지한다.
- Hosted의 관리자 설정 `WEBNOVEL_METADATA_COLLECTOR_REMOTE_AUTH_ENABLED` 제한은 그대로 유지한다.
  활성화된 서버에서는 원격 브라우저 없이 공개 검색 capability를 사용할 수 있다.
- 오프라인 회귀 검사는 쿠키 없는 검색·상세, 일반판/성인판 분리, 두 설정의 opt-in, 저장 후 재시작, 다른 로그인
  보존 및 실패 응답을 포함한다. 위 실사이트 실측은 개발 PC에서의 결과이며 운영 서버 IP에서의 성공 보장은 아니다.
- 네이버 시리즈의 실제 로그인·성인 권한 검증과 쿠키 가져오기는 다음 작업이다.

## 플랫폼별 직접 인증 검토 (2026-09-09, 카카오페이지 계획은 위 공개 API 구현으로 대체)

노벨피아의 `LOGINKEY`는 해당 사이트가 실제 콘텐츠 요청에 사용하는 단일 쿠키이므로 서버가 직접 발급·검증하기
쉽다. 다른 플랫폼은 같은 이름이나 같은 입력 형식을 억지로 맞추지 않고, 수집기 어댑터가 아래 인증 capability와
필요한 비밀 필드, 로그인 확인 probe를 선언하는 형태가 적합하다.

- `public_adult`: 별도 로그인 없이 사용자가 성인 검색을 명시적으로 켰을 때만 실행한다.
- `token`: 사이트가 콘텐츠 세션에 직접 인정하는 불투명 토큰을 저장한다.
- `cookie_bundle`: 사용자가 전용 브라우저에서 얻은 허용된 쿠키 이름만 가져와 서버 private volume에 저장한다.
- `browser_profile`: 쿠키 외 브라우저 상태가 필요할 때 현재 전용 프로필 경로를 사용한다.

플랫폼별 판정은 다음과 같다.

1. **리디**: 현재 구현은 로그인 세션을 쓰지 않고 공개 검색 JSON의 `age_limit >= 19`를 사용한다. 따라서 UI와
   계약도 `public_adult`로 표현하는 것이 맞다. 계정 비밀번호나 브라우저 프로필을 요구할 이유가 없다.
2. **네이버 시리즈**: `NID_AUT`와 `NID_SES` 쿠키를 사용자가 명시적으로 가져오는 `cookie_bundle` 방식은 구현
   가능성이 높다. 네이버 공식 로그인 API는 등록 애플리케이션의 OAuth 토큰을 발급하는 계약이므로, 그 토큰을
   시리즈 웹 로그인 쿠키로 간주하지 않는다. 아이디·비밀번호 직접 로그인을 자동화하면 암호화 로그인, 기기 확인,
   CAPTCHA와 2단계 인증 변화에 계속 종속된다. 쿠키를 저장한 뒤 대표 성인 작품 검색 probe가 성공한 경우에만
   연결됨으로 표시하고, 만료 시 다시 가져오도록 하는 편이 안정적이다.
3. **카카오페이지**: 카카오 로그인 REST API의 앱 access token도 카카오페이지 웹 세션과 같은 계약이 아니다.
   과거 도구가 여러 쿠키를 사용한 사례는 있지만 현재 필드와 만료 규칙을 보장하지 못한다. 실제 로그인 세션에서
   필요한 쿠키·저장소 항목을 최소 한 번 실측하고, 허용 목록과 성인 작품 probe를 고정한 뒤 `cookie_bundle` 또는
   `browser_profile` 중 하나를 선택해야 한다. 실측 전에는 아이디·비밀번호 직접 저장 방식을 추가하지 않는다.

권장 구현 순서는 리디 설정 화면의 불필요한 로그인 요구 제거, 네이버 쿠키 묶음 가져오기와 대표 작품 회귀 검사,
카카오페이지 실세션 캡처·최소 필드 확정 순이다. 모든 비밀은 기존 수집기 private volume에만 저장하고 Moya DB,
브라우저 저장소, 설정 동기화, 로그와 일반 API 응답에서 제외한다.

## 누적 장애 및 해결

### 전용 로그인 창에서 로그인이 차단됨

- 증상: 자동화 브라우저에서 로그인 자체가 거부되거나 정상 진행되지 않았다.
- 원인: 로그인 화면을 Playwright가 직접 제어하는 브라우저로 열어 사이트의 자동화 방어에 걸렸다.
- 해결: 로그인 단계는 자동화 연결이 없는 시스템 Chrome/Edge를 전용 프로필로 실행한다. 사용자가 창을 닫고 완료 체크를 한 뒤에만 같은 프로필을 Playwright 검색 컨텍스트로 연다.

### 로그인 완료 직후 프로필을 열지 못함

- 증상: 로그인은 됐지만 완료 체크 또는 첫 검색에서 인증 프로필 사용 오류가 났다.
- 원인: 로그인 창의 하위 프로세스가 남아 Chrome 프로필 잠금이 즉시 풀리지 않았다.
- 해결: 완료 처리에서 전용 로그인 프로세스 트리를 종료하고 잠금 해제를 짧게 기다린 뒤 검색 컨텍스트를 준비한다. 실패 시 제한된 횟수만 재시도하고 사용자에게 전용 창 종료를 안내한다.

### 인증 검색 중 컨텍스트 충돌

- 증상: 간헐적으로 로그인 세션 만료 또는 페이지 요청 실패가 발생했다.
- 원인: 하나의 영구 프로필에서 여러 인증 요청과 컨텍스트 복구가 겹칠 수 있었다.
- 해결: 인증 프로필 요청은 직렬화하고, 예상한 컨텍스트만 재설정하며, 끊어진 컨텍스트는 한 번 다시 연결한다.

### 노벨피아 `창작물 속으로`가 다른 작품으로 선택됨

- 증상: 19세 작품 검색은 됐지만 비슷한 공개 작품이 최종 결과로 선택됐다.
- 원인: 공개 후보와 인증 후보를 합칠 때 제목의 문자 그대로 일치 여부보다 다른 품질값이 앞설 수 있었다.
- 해결: 문자 그대로의 제목 일치를 최종 동률 해소 기준으로 사용한다. 다만 플랫폼이 제목을 조금 다르게 표기하는 일반 사례를 막지 않도록 유사 제목 후보는 계속 허용한다.
- 대표 작품: 노벨피아 `창작물 속으로` 인증 작품 ID `610`.

### 노벨피아가 익명 세션을 로그인 성공으로 표시하고 19세 검색은 0건이 됨

- 증상: 일반 공개 작품 검색은 되지만 알려진 노벨피아 19세 작품 검색은 항상 0건이었다. UI에서 로그인 완료를
  눌러도 인증 검색 사용 상태로 표시됐다.
- 원인: 기존 구현은 브라우저 창을 연 뒤 사용자의 완료 선언만 저장했고 실제 로그인 여부를 확인하지 않았다.
  노벨피아 `/proc/novel?novel_age=19`는 익명 세션에도 HTTP 200과 빈 목록을 반환하므로, 예외가 없다는 사실은
  인증 성공 증거가 아니다.
- 해결: 노벨피아는 브라우저 자동화를 사용하지 않는다. 이메일 계정은 `/proc/login`에 서버가 만든 `LOGINKEY`를
  함께 보내 활성화하고, 소셜 계정은 사용자가 키를 직접 입력한다. 양쪽 모두 `/proc/member_adt_mode`가 `OK`를
  반환해야 연결을 활성화한다. `login`은 만료, `auth`는 본인 인증 필요로 구분한다.
- 복구: 이메일 계정은 저장된 자격 증명으로 키를 한 번 자동 갱신한다. 수동 키는 명시적인 재입력 안내를 반환한다.
- 저장: 이메일·비밀번호와 키는 수집기 전용 `novelpia-auth.json`에만 저장하며 Moya DB, 브라우저 저장소와 일반
  동기화에는 포함하지 않는다. `로그인 세션 삭제`가 이 파일도 삭제한다.
- 근거: `NovelpiaDownloader`의 공개 README와 요청 구현에서 이메일 로그인은 `/proc/login`과 `LOGINKEY`를,
  이후 작품 요청은 `Cookie: LOGINKEY=...`를 사용함을 확인했다. 라이선스 파일이 없어 코드는 복사하지 않고
  관찰한 HTTP 계약만 독립 구현했다.

### 노벨피아 `아포칼립스의 암컷조련사` 표지가 기본 이미지로 반환됨

- 증상: 작품은 찾았지만 `og:image`의 노벨피아 공용 이미지가 표지로 반환됐다.
- 원인: 상세 페이지의 공용 Open Graph 이미지가 실제 표지 요소보다 먼저 선택됐다.
- 해결: 상세 페이지의 `img.cover_img` 원본 표지를 우선하고, 공용 placeholder가 아닌 경우에만 `og:image`를 대체 경로로 사용한다.
- 대표 작품: 노벨피아 작품 ID `426992`, 실제 표지 `imagebox/cover/..._ori.file` 경로 확인.

### 네이버 시리즈 `네이키드 베이비`가 검색됐지만 `not_found`로 반환됨

- 증상: 인증 검색 응답에는 연재본 ID `14445233`과 단행본 ID `12513961`이 모두 있었지만 API는 작품을 찾지 못했다고 반환했다.
- 원인: 시리즈가 연재본 제목을 `네이키드 베이비(Naked Baby) [BL]`로 제공한다. 기존 제목 정규화가 영문 병기와 `[BL]`을 본제목에 포함해 검색어 `네이키드 베이비`와의 점수를 `0.56`으로 계산했고, 자동 선택 기준 `0.90` 아래에서 탈락시켰다. 단행본의 회차 표기 `총 5권`도 제거하지 못했다.
- 해결: 괄호 속 영문 번역명과 `[BL]`·`[GL]` 장식 표시는 제거하고, `총 N화`뿐 아니라 `총 N권`도 회차 접미사로 제거한다. `[단행본]`은 판본 구분에 필요하므로 유지해 연재본보다 우선되지 않게 한다.
- 대표 작품: [네이키드 베이비](https://series.naver.com/novel/detail.series?productNo=14445233), 작가 `아이러빗`.

### 리디 인증 검색이 항상 로그인 오류로 실패함

- 증상: 리디 로그인과 사용 설정을 마쳐도 인증 검색이 `403`과 함께 로그인 또는 성인 인증 필요로 표시됐다.
- 원인: 로그인 세션 문제가 아니라 리디 앞단의 Cloudflare challenge였다. 전용 프로필을 headless 브라우저로 열면 리디 홈과 검색 API 모두 `Just a moment...` 페이지로 전환되며 403을 반환했다.
- 해결: 리디 19세 검색은 브라우저 페이지 이동을 사용하지 않는다. 공식 검색 API의 일반 HTTP 응답에서 `age_limit >= 19`인 웹소설 연재 후보만 선택한다. 이 경로도 사용자가 UI에서 `19세 작품 포함`과 리디 사용을 켠 경우에만 실행한다.
- 대표 작품: 리디 `상수리나무 아래`, 작품 ID `1922000007`.
- 제한: 공식 검색 API까지 Cloudflare 정책이 확대되거나 응답 형식이 바뀌면 리디 수집기를 다시 점검해야 한다.

### 리디 `러브:제로(Love:Zero)`가 짧은 제목으로 선택되지 않음

- 증상: `러브제로`와 `러브:제로` 모두 리디 검색 응답에는 작품이 있었지만 API가 `not_found`를 반환했다. 전체 표기 `러브:제로(Love:Zero)`로만 성공했다.
- 원인: 제목 정규화가 괄호 속 단순 영문 병기는 제거했지만 `Love:Zero`처럼 콜론이 포함된 영문 병기를 보존했다. 후보 정규화 결과에 `lovezero`가 붙어 일치 점수가 `0.5`로 낮아졌다.
- 해결: 괄호 안에 영문자가 있고 한글과 판본 표지가 없는 경우 구두점 종류와 관계없이 영문 병기로 제거한다. 제목 본문의 콜론·공백 제거 규칙은 그대로 사용한다.
- 대표 작품: 리디 `러브:제로(Love:Zero)`, 작품 ID `5721000001`.

## 장애 확인 순서

불필요한 반복 요청 없이 아래 순서로 한 번씩 분리해 확인한다.

1. 플랫폼 사용 설정과 `19세 작품 포함` 값이 실제 요청에 반영됐는지 확인한다.
2. 인증 검색 응답에 목표 작품 ID 또는 제목이 존재하는지 확인한다.
3. 응답에 있는데 후보가 없다면 플랫폼 파서의 선택자와 성인 표시 판정을 확인한다.
4. 후보가 있는데 최종 결과가 없다면 제목·작가 정규화 점수와 판본 구분을 확인한다.
5. 작품은 찾았지만 표지가 없다면 상세 페이지의 실제 표지 요소와 placeholder 판정을 확인한다.
6. 수정 후 해당 대표 작품을 UI에서 한 번 검색하고 표지 로드까지 확인한다.

## 알려진 제한

- 세션이 필요한 네이버 시리즈·노벨피아는 사용자의 계정에서 해당 플랫폼의 성인 인증이 끝나 있어야 한다.
- 사이트가 추가 본인 확인, CAPTCHA 또는 재로그인을 요구하면 사용자가 전용 로그인 창에서 직접 처리해야 한다.
- 플랫폼의 검색/상세 HTML 또는 내부 API 형식이 바뀌면 해당 플랫폼 파서를 수정해야 한다.
- 원본 표지 URL은 provenance로 반환하고, Moya 적용용 이미지는 짧은 수명의 opaque cover ref를 통해 공개 표지만
  제한적으로 전달한다. 임의 URL 프록시나 인증 제한을 우회하는 프록시는 제공하지 않는다.
