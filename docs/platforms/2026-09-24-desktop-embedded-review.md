# 내장 self-host 데스크톱 구현 검토

검토 기준: `773f055` 및 이 문서와 함께 적용한 두 오류 수정. 기준 계획은 [내장 self-host 계획](2026-09-23-desktop-embedded-selfhost-plan.md)이다. 보관한 IndexedDB 확장 계획을 구현 기준으로 사용하지 않았다.

## 판단

**P0 완료, P1의 기본 사용 흐름을 검증한 후보 앱 상태다. 일반 사용자 배포 완료 상태는 아니다.** 데스크톱은 기존 서버 DB·파일 저장소와 Remote reader를 사용한다. 순수 웹의 기존 IndexedDB 기능이 코드에 남아 있다는 사실과 데스크톱 서재를 IndexedDB 정본으로 확장하는 것은 구분한다.

## 재현하여 수정한 오류

1. **터널 시작 직후 종료를 연결 성공으로 표시 (보통).** `embedded-tunnel.mjs`는 주소와 연결 로그가 모두 오면 대기문을 빠져나오면서 그 사이 자식이 종료됐는지 확인하지 않았다. 연결 로그를 출력하고 바로 종료하는 실제 자식 프로세스로 성공 반환을 재현했다. 성공 반환 직전에 취소 상태와 자식 종료 상태를 확인하도록 수정했다. 같은 검사는 수정 전 실패, 수정 후 통과했다.
2. **일시적인 native 상태 조회 오류 뒤 조회가 영구 중단 (보통).** `EmbeddedServerGate`에서 조회 오류를 만나면 다음 조회를 예약하지 않았다. 서버는 실행 중인데 UI는 오류에 머물고, 실행 중이라 재시도 버튼도 나오지 않았다. 조회 실패 후 상태 조회를 계속하고 성공 시 해당 연결 오류만 지우도록 수정했다. 시작/종료 명령 자체의 오류와 분리했다. 실패 한 번 뒤 정상 응답이 오는 검사로 수정 전 실패와 수정 후 회복을 확인했다.

## 완료 범위와 실제 증거

| 범위 | 확인한 결과 |
| --- | --- |
| Docker 없는 실행 구성 | Node·PostgreSQL·Redis·파일 객체 저장소·기존 API/worker 동봉 후보 구현 |
| Windows 앱 | 이동한 한글 경로에서 자동 서버 시작, 실제 WebView의 TXT 읽기, 종료/재시작, 트레이 유지 통과 |
| 공유 서재 | 기존 계정 로그인, 공통 QR/주소 복사, LAN 접근/읽던 위치 변경/해제 통과. 같은 CI PC에서 별도 브라우저로 검사 |
| Cloudflare 기본 접속 | 기본 선택·동봉 실행·취소/해제 구현. Linux에서 실제 Quick Tunnel HTTPS 로그인/세션 쿠키/해제 통과 |
| 다른 접속 방식 | LAN/Tailscale IPv4 직접 접속 및 고정 Cloudflare 터널 입력/실행 경로 구현. 실제 Tailscale 타 기기와 고정 도메인 검증은 남음 |
| 인증 경계 | 공개 gateway의 Host/Origin 검사, 소유자 bearer 및 계정 초기화/복구 전달 차단, HTTPS 쿠키의 Secure 설정 검사 |
| 기존 데이터 보호 | 기존 IDB 확장은 별도 보관. 이번 검증은 새 검증 프로필만 사용하며 사용자 데이터 이전 완료를 뜻하지 않음 |

기존 Windows 증거는 [`35885884320`](https://github.com/west-truth/moya-reader/actions/runs/35885884320), 코드 기준 `aa36f2c`다. 이번 두 수정의 Windows 재검증과 혼동하지 않는다. 실제 서비스 연결 검사는 기존 성공 기록을 사용하고 같은 공개 터널 검사를 반복하지 않았다.

이번 수정 후 로컬에서 gateway/터널 검사 **3개**, UI·reader runtime·파일 저장소·웹 자산 검사 **5개 파일 22개**를 통과했다. 프런트 TypeScript 검사와 변경 파일 lint도 통과했다. 두 회귀 검사는 Windows 후보 CI에도 추가했다.

## 남은 문제와 배포 완료 조건

- **비정상 종료 후 자동 복구 미구현 (높은 우선순위).** `server.lock`은 정상 종료 때 지워진다. 전원 종료 등으로 남으면 다음 실행이 차단되며, 앱에서 복구할 경로가 없다. 실제 소유 프로세스와 DB 상태를 확인하는 복구가 필요하다. 단순히 lock을 무조건 삭제하면 안 된다.
- **일반 Windows 설치 조건 미완료 (높은 우선순위).** 현재 산출물은 debug 후보 폴더다. Visual C++ runtime·WebView2가 없는 새 PC에서 사용자가 별도 설치하지 않아도 실행되는 설치/준비 경로와 재배포 조건 검증이 필요하다. 개발 도구가 설치된 CI 성공만으로 충족되지 않는다.
- **실제 원격 기기 및 Windows Cloudflare 연결 검증 미완료.** Windows LAN과 Linux Quick Tunnel 성공을 실제 다른 휴대폰·Windows Quick Tunnel·사용자 고정 터널의 성공으로 확대해석하지 않는다.
- **연결 상태 표시의 범위.** 현재 터널 생성/프로세스 종료는 감지하지만, 연결기가 살아 있는 채로 인터넷이 끊겼을 때 UI의 연결 상태를 정밀하게 갱신하지 않는다. 재연결 상태 검사가 남는다.
- **공통 숫자 퍼센트 UI 미연결.** 계획의 원형 진행률 중앙 숫자 퍼센트를 새 서버 실행 경로에 연결하지 않았다. 기존 일부 기능의 progress 값이 있다는 사실로 완료 처리하지 않는다.
- **P2 기능 검증과 자료 이전 미완료.** 대용량 대표 파일, 백업/복원, EPUB·PDF·만화, 소스/확장·AI/TTS, 작업 중단/저장 공간 부족, 기존 프로필 이전은 후보 앱에서 지원표와 완료 증거가 필요하다. 기존 웹 기능 전부가 앱에서 검증됐다고 주장할 수 없다.
- **P3 서버 간 동기화 미구현.** 여러 기기가 같은 서버를 여는 것은 구현됐지만 독립 서재의 양방향 복제·오프라인 재전송·충돌 처리 완료를 뜻하지 않는다.

다음 구현 단위는 P1의 비정상 종료 복구와 설치 실행 조건이다. 새 저장 체계나 별도 데스크톱 리더를 추가할 이유는 발견하지 않았다.

## 후속 구현 (2026-09-24)

위 검토의 미구현 목록은 검토 당시 기준이다. 이후 다음 항목을 구현했다.

- 검토의 두 수정은 Windows 실행 [`35904788387`](https://github.com/west-truth/moya-reader/actions/runs/35904788387)에서도 통과했다.
- `moya-server-guard`가 OS 프로필 잠금을 보유하며 Node launcher를 실행한다. 이전 launcher가 사라졌을 때 API/worker 종료를 기다리고, PostgreSQL의 실행 파일·데이터 경로·시작 시각 및 Redis 인증을 확인한 뒤 정리한다. 소유권 불확실·기록 손상 시 중단한다. Linux의 실제 launcher 강제 종료, 중복 차단, 계정/endpoint 보존 및 정상 종료 검사를 통과했다.
- Windows 첫 복구 검사에서 열린 `server.lock` 파일의 atomic rename이 EPERM으로 실패했다. 초기 기록을 동기화하고 파일 핸들을 닫도록 수정했다. 프로필 독점은 별도의 OS 잠금으로 유지한다.
- Windows NSIS 후보에 Microsoft 서명 확인을 거친 VC 런타임과 WebView bootstrapper를 포함했다. 설치본을 개발 도구 PATH 없이 실행하는 CI 검사를 추가했다. 일반 새 PC에서 필수 구성 미설치 상태와 오프라인 최초 설치는 별도 검증 대상이다.
- 공통 원형 진행률 중앙의 숫자 %, 서버 이미지 저장 수 전달 및 단계 전환 초기화를 추가했다. 미확정 총량에 임의 퍼센트를 부여하지 않는다.
- 529MiB 만화 실제 가져오기 중 청크 수신에만 남아 있던 500MiB 제한을 발견해 공통 서버에서 수정했다. 이후 UI 가져오기, 이미지 표시, 원본 해시 일치를 통과했다.
- 실제 서버 ZIP을 새 프로필에 복원하여 작품 ID·원본·독서 위치·재시작 보존을 확인했다. 복원 시 작품 `updated_at`이 갱신되는 기존 정책은 비교에서 명시적으로 구분했다.

측정값과 남은 기능은 [P2 지원표](2026-09-24-desktop-feature-support.md)에 기록했다. P1/P2 전체 완료나 일반 배포 완료로 표시하지 않는다.
