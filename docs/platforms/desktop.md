## 제품 구조

목표는 **기존 self-host를 Windows에서 앱처럼 쓰는 것**입니다. 서재 한 곳을 여러 화면에서 이용합니다.

```text
서버가 없는 사용자: Windows 앱 → 앱에 포함된 기존 self-host → DB·원본 파일
                                      ↑
                             다른 기기의 브라우저

서버가 있는 사용자: Windows 앱 / 브라우저 → 사용 중인 self-host → DB·원본 파일
```

- 저장·가져오기·수집기·독서·AI/TTS·백업은 기존 공통 서버를 재사용합니다.
- 다른 기기 접속은 같은 서버의 주소와 로그인으로 처리합니다. LAN·터널·Tailscale 같은 연결 방식은 저장 모델과 독립적입니다.
- 서재 이전에는 백업·복원을 사용합니다. 두 서버에 따로 생긴 변경을 자동 병합하지 않습니다.
- 기존 브라우저 캐시와 서버 사이의 `/api/sync`, `/api/sync/events`는 계속 필요합니다. 서버 간 복제와 구별합니다.

**구현 사실:** 내장 서버 자동 시작·공유와 기존 서버 주소 선택이 있습니다. 선택한 기존 서버는 다음 앱 시작에 별도 WebView 창에서 해당 서버의 웹 화면과 로그인으로 열립니다. 앱의 로컬 서재는 그대로 보관되며 두 서재는 자동으로 합쳐지지 않습니다.

**외부 서버 버전 조건:** 구버전 웹 화면은 Tauri의 전역 객체 때문에 자신을 네이티브 앱으로 오인할 수 있습니다. 추가 검토 수정본은 서버가 제공하는 `index.html`의 `moya-desktop-webview=browser-v1` 선언을 확인한 뒤 창을 엽니다. 선언이 없는 서버는 웹 화면까지 업데이트하거나 일반 브라우저로 접속해야 합니다. 이 경로의 Windows 검증 결과는 [PR #62](https://github.com/west-truth/moya-reader/pull/62)의 최신 검증 기록에서 확인합니다.

## 필요성과 비용 판단

| 작업                                           | 판단                               | 근거                                                                                             |
| ---------------------------------------------- | ---------------------------------- | ------------------------------------------------------------------------------------------------ |
| 내장 self-host의 시작·종료·설치·데이터 보존    | 필요                               | 서버를 별도 설치하지 않고 로컬에서 사용하기 위한 앱 경계                                         |
| 기존 서버 직접 접속                            | 구현, Windows 기본 검증 통과       | 이미 서버가 있는 사용자는 같은 서재를 그대로 이용해야 함                                         |
| 같은 서버의 원격 접속                          | 필요                               | PC를 켜 두고 다른 기기에서 읽는 요구                                                             |
| 기존 백업으로 자료 이전                        | 필요                               | 서버를 옮기는 일회성 작업                                                                        |
| 독립 서버 간 원본·주석·삭제의 양방향 자동 복제 | 현재 범위에서 제외                 | 두 서재를 독립 편집해야 하는 요구가 없고, 모든 새 데이터 종류마다 충돌·삭제·재시도를 구현해야 함 |
| 대용량 IndexedDB를 별도 네이티브 저장소로 교체 | 현재 데스크톱의 선행 과제에서 제외 | 실제 자료는 기존 서버의 DB·파일 저장소가 담당                                                    |

기능을 추가하기 전에 사용자에게 **어떤 사용 흐름이 필요한지, 기존 경로로 가능한지, 변경할 공통 코드와 유지비가 무엇인지** 설명합니다.
공유 코드를 쓴다는 이유만으로 새로운 동기화 모델을 추가하지 않습니다. 과거 W01~W12는 현재 완료 목록이 아닙니다.

## 이번 정리의 경계와 검토

원본 전체는 `archive/desktop-peer-sync-20260924` (`83236ac`)에 보관했습니다.
정리 브랜치는 `refactor/desktop-single-server`, 코드 정리 커밋은 `cb833c8`입니다. 사용자 DB에 삭제·다운그레이드 명령을 실행하지 않습니다. 이전 구현이 이미 남긴 데이터나 파일도 이번 작업에서 일괄 삭제하지 않습니다.

## 남은 필요한 작업

1. **업데이트·공개 배포 검증:** Windows 설치 후보는 개발 도구를 PATH에서 숨긴 CI 러너에서 기동을 확인했습니다. 기존 설치본의 식별자와 profile을 확인하고 사본으로 자료 승계를 검증해야 합니다. 공개 배포용 의존성 고지 게이트는 아직 차단됩니다.
2. **자료 이전 확인:** 실제 사용할 기존 백업 형식과 지원 범위를 확인합니다. 거부 중인 모든 과거 형식을 미리 구현하지 않습니다.
3. **실제 연동:** 필요한 계정·키가 있을 때 사용할 수집기·AI/TTS·네트워크 연결만 확인합니다.

물리적 다른 기기 검증은 이번 범위에서 제외합니다. 앱 내부 Tailscale 자동 설정은 아직 구현된 것으로 표시하지 않으며,
필요 시 네트워크 접속 편의 기능으로 별도 판단합니다. 두 서버 동기화를 그 선행 조건으로 만들지 않습니다.

## 검증 결과

**최신 후보는 0.1.1-beta.1입니다.** [PR #62](https://github.com/west-truth/moya-reader/pull/62)에 최신 CI와 Windows 앱·설치·업데이트 검증 결과를 기록합니다. 아래는 각 커밋 당시의 기록이며 최신 후보의 결과로 합산하지 않습니다. 공개 베타 게시 여부는 [후보 안내](../releases/0.1.1-beta.1.md)를 참조합니다.

- 공통 sync 전체, 주석/독서 위치, 서버 인증 경계, 백업·복원, 가져오기 기준 revision, reader-state 복원, 내장 서버 UI를 묶은 **19개 파일·90개 검사 통과**.
- 별도 가져오기·페이지 재사용·삭제 검사 묶음 **41개 통과**. 여기의 3개 skip은 명시적으로 비활성화된 성능 benchmark이며 기능 검사 통과 수에 포함하지 않음.
- 수정 전 실제 저장 경로에서 실패했던 3개 검사도 최종 정리 코드로 다시 실행해 모두 통과했습니다.
- 웹·서버 타입 검사, 변경 파일 ESLint, 공통 계약/공개 소스 경계, 서버 production build 검증 통과.
- 정리본 내장 서버는 [Windows 실행 36118626358](https://github.com/west-truth/moya-reader/actions/runs/36118626358)에서 검증했습니다. 기존 서버 직접 접속을 포함한 `6e347a0`은 [Windows 실행 36126788910](https://github.com/west-truth/moya-reader/actions/runs/36126788910)에서 외부 WebView 로그인·다운로드·파일 가져오기·백업, 로컬 복귀와 기존 TXT/EPUB/PDF·공유·복원·재시작 회귀가 모두 통과했습니다.
- `c6dac1d`의 [Windows 설치 후보 실행 36128734373](https://github.com/west-truth/moya-reader/actions/runs/36128734373)은 같은 앱 회귀와 설치 후 동봉 서버 기동에 성공했습니다. `cleanMachine: false`인 러너 검사이며 실제 이전 설치본의 profile 승계는 확인되지 않았습니다.
- 설정창에서 직접 외부 서버를 선택하는 경로는 `4966302`의 [Windows 실행 36131029201](https://github.com/west-truth/moya-reader/actions/runs/36131029201)에서 전체 성공했습니다. 설치 후보 실행과 제품 코드는 동일하며 검사 스크립트와 실패 재시도 단위 검사만 보강했습니다.
- DB migration 파일은 변경하지 않았고 운영 데이터에 대한 정리 명령도 실행하지 않음.

주요 재현·검사 위치:

- `apps/server/test/client-sync-consistency.integration.test.ts`: 실제 PostgreSQL에서 commit 순서 역전, 위치 저장 실패/중복/동시 삭제, 다른 작품의 메모 변경 차단.
- `apps/server/src/routes/sync/sync-contract-matrix.test.ts`: 기존 v1/v2 클라이언트 사건 계약.
- `apps/server/src/services/import-page-reuse.integration.test.ts`: append·원본·표지·GC·백업 복원·영구 삭제.
- `apps/server/src/services/import-expected-base.integration.test.ts`: 동시 교체 차단과 현재 원본만 담는 백업.

이 결과는 확인한 경로의 회귀 근거이며 전체 제품의 무결함 보장이 아닙니다. 설치본 업데이트, 물리적 다른 기기, 실제 유료 연동 검증은 별도 범위입니다.
