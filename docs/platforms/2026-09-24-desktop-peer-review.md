# 직전 에이전트 변경 검토와 수정

검토 기준: `feat/desktop-embedded-selfhost`, `72e0e6e`. 수정은 `a59cc9f`와 Windows 검사 보정 `19a0d65`로 커밋·푸시했다.

## 결론

공통 웹 UI → 기존 self-host API/worker → 서버 DB·파일 저장소라는 구현 방향은 계획과 일치한다. 초기 복제도 기존 서버 백업 경로를 재사용한다. 다만 아래 오류가 있어 그대로 완료로 판단할 수 없었다.

| 우선순위 | 확인한 문제                                                                                                                                      | 수정과 확인 방법                                                                                                                                                                                                                                                                                                     |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P1       | 독서 위치 PATCH의 SQL 내부 잠금은 대기 전 snapshot을 사용한다. 먼저 대기하던 DELETE가 완료되어도 오래된 PATCH가 삭제된 위치를 되살릴 수 있다.    | transaction 안에서 잠금을 별도 SQL로 먼저 획득한다. 실제 PostgreSQL 잠금 뒤 DELETE→과거 PATCH를 대기시켜 수정 전 실패를 재현했고, 수정 후 위치가 없는 상태와 `applied: false`를 확인했다.                                                                                                                            |
| P1       | 계정 session 만료 후 공통 UI에서 기존 연결을 복구할 수 없다. 다시 연결하면 cursor 초기화 또는 비어 있지 않은 서재 거부에 걸린다.                 | `/api/sync/peer/reauthenticate`와 재로그인 폼 추가. 상대 서버 ID를 확인하고 암호화한 session만 교체한다. 연결 ID·양방향 cursor를 보존하며 만료 중 쌓인 독서 위치 변경까지 전달됨을 검사했다. 잘못된 비밀번호는 기존 비밀·cursor를 바꾸지 않는다.                                                                     |
| P1       | 연결 직후 최초 복제 요청 전에 창/서버가 종료되면 DB 상태가 `ready`여서 복제 재시도를 찾을 수 없다. 최초 인증 실패도 복제 상태에 반영되지 않는다. | migration `0053`의 `bootstrap_required`와 `awaiting_bootstrap` 상태를 사용한다. 복제가 필요한 연결은 백그라운드 동기화를 멈추고 복원 commit에서만 준비 완료로 바뀐다. 서버 재시작, 복제 전 session 만료·재로그인, 누락 원본 실패·재시도를 검사했다. 이전 버전의 명확한 복제 중단/실패 기록도 migration에서 표시한다. |
| P2       | 다운로드 바이트는 접근성 속성에만 있고 화면에 보이지 않는다. ZIP 검증 중에도 다운로드 상태가 유지된다.                                           | 바이트 수를 화면 텍스트로 표시하고 staging의 실제 검증 시작 시점을 진행 단계에 연결했다. 바이트 표시의 수정 전 실패와 수정 후 통과를 확인했다.                                                                                                                                                                       |

기존 `books.test.ts`의 독서 위치 검사 3개도 transaction 도입을 반영하지 않아 실패했다. transaction mock을 갱신하고 잠금→쓰기→event→commit 및 실패 시 rollback/release를 확인하도록 수정했다. 실제 원자성·동시 실행 검사는 별도 PostgreSQL 통합 검사로 수행한다.

## 검증 결과

- 후속 Windows: [`19a0d65`, 실행 35960786910](https://github.com/west-truth/moya-reader/actions/runs/35960786910) 전체 성공. 실제 WebView에서 복제 전 요청 중단→설정창 다시 열기→재시도, source session 만료→기존 연결 재로그인→cursor 유지까지 확인했다. `app-smoke-result.json`의 `nativePeerCopyResumed`, `nativePeerReauthenticated`가 모두 true다. 설치본 생성 옵션은 켜지 않았다.
- 관련 8개 파일에서 **49개 통과, 1개 의도적 제외**. 변경하지 않은 513MiB 백업 왕복 검사를 반복하지 않았다.
- 실제 PostgreSQL/HTTP 통합 검사: 두 서버 최초 복제, 재시작, 인증 만료/복구, 독서 위치 교환·충돌, event 실패 시 rollback, 삭제/과거 저장 동시 실행.
- 관련 단위 검사: books, sync, sync-reader-events, sync-contract-matrix, 공통 설정 화면, backup staging.
- 서버·웹 TypeScript 검사, 변경 TypeScript/TSX 파일 ESLint 통과.
- 이번 수정으로 Windows 실행기/설치 패키지는 바꾸지 않았다. Windows WebView 검증은 위 후속 실행으로 완료했고 새 설치본의 최초 설치 검증은 포함하지 않는다.

## 남은 범위

- 현재 스트리밍 ZIP은 `Content-Length`가 없어 첫 복제에는 **바이트 수·단계**가 표시된다. 총량이 있는 전송만 숫자 퍼센트를 표시하며 전체 복원 퍼센트가 구현됐다는 뜻은 아니다.
- 첫 복제 이후 작품·원본·주석 등 전체 증분 동기화는 여전히 미구현이다. 이번 수정은 D1 복구와 독서 위치 처리 경계의 보완이다.
- 대용량·물리 타 기기·새 PC 설치 검증은 기존 인계 문서대로 남아 있다. 이전 Windows 종료 시간 초과 한 건의 원인도 이번 검사로 해결됐다고 단정하지 않는다.
- 이전 버전에서 복제 시도/실패 기록조차 없이 `ready`로 남은 연결의 원래 의도는 migration으로 추측하지 않는다. 이번 수정 후 새로 만든 UI 연결부터 최초 복제 의도가 명시적으로 저장된다.
