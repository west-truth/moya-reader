## 재사용 판단

| 코드군                                          | 처리                                               |
| ----------------------------------------------- | -------------------------------------------------- |
| 파일 선택·범위 읽기·스트리밍·무결성 검사        | 기존 서버의 같은 기능과 대조 후 필요한 부분만 선별 |
| 공통 원형 퍼센트·단계/attempt/sequence          | 서버 진행률 연결에 필요한 UI/계약만 선별           |
| 대용량·중단·복원 fixture                        | 실제 새 경로를 검증하도록 필요한 입력/검사 재사용  |
| IndexedDB와 파일 사이 활성화·복구·snapshot 복원 | 새 서버의 선행 기반으로 사용하지 않음              |
| 미완성 기존 Blob → native 파일 이전             | 개발 중단, 보관 상태 유지                          |

## 보존 확인과 재개 규칙

- 보관 commit은 Git으로 다시 열 수 있다. 작업 중 변경을 삭제하거나 일괄 되돌린 방식이 아니다.
- 기존 프로필·MoyaData·운영 DB는 이 브랜치 분리로 변경하지 않았다. 구버전 코드로 새 스키마의 사용자 프로필을 열어서는 안 된다.
- 현재 `main` 및 다른 worktree의 미커밋 변경은 손대지 않았다.
- 보관 브랜치의 과거 계획 두 문서에는 중단/새 계획 안내를 추가했다. 그 문서의 A~E 잔여 목록을 다시 수행하지 않는다.
- 새 브랜치에서 코드를 가져올 때마다 선택 이유, 가져온 범위, 관련 검사만 남긴다. 보관 브랜치 전체를 병합하는 방식으로 옛 구조를 되살리지 않는다.
