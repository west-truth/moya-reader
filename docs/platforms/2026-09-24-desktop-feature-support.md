# 내장 서버 앱 기능 연결과 검증 현황

기준: `feat/desktop-embedded-selfhost`, 2026-09-24. [구현 계획](2026-09-23-desktop-embedded-selfhost-plan.md)의 P2 지원표다. 기존 코드가 있다는 것과 후보 앱에서 검증을 통과했다는 것을 구분한다. 수집기 포함 Windows 기본 후보는 [`775a9ff` 실행](https://github.com/west-truth/moya-reader/actions/runs/35929350327)에서 통과했다. 실제 앱 기능과 설치 후보는 [`62514e5` 실행](https://github.com/west-truth/moya-reader/actions/runs/35932538748)에서 통과했다. 최신 코드 `abb418c`의 Windows 앱·복구·공통 독서 회귀는 [실행 35953318186](https://github.com/west-truth/moya-reader/actions/runs/35953318186)에서 통과했다(설치본 생성 옵션 제외).

다음 구현의 파일·작업 순서·완료 검사는 [실행 지침](2026-09-24-desktop-next-work-handoff.md)을 따른다. A1~A3은 기존 self-host 수집기와 로그인 브라우저를 앱에 연결하고 실제 Windows 패키지에서 검증했다. C0/D0 조사는 별도 문서에 기록했다. C1의 기본 로컬 ZIP 이전과 D1의 빈 서재 최초 복제·신규 독서 위치 교환을 검증했다. 이후 작품·원본 변경과 나머지 동기화 항목은 남았다.

수집기 포함 Windows 설치 후보는 **276,188,625 bytes**이며 설치 후 개발 도구를 PATH에서 제거한 상태에서 동봉 서버 시작·종료를 통과했다. 런타임 payload는 **862,344,665 bytes**이고, 그중 수집기 서비스·라이선스 파일은 **60,525,066 bytes**, 로그인 Chromium은 **286,993,460 bytes**다. payload 수치는 앱 실행 파일·설치 선행 구성을 제외한다. CI runner는 VC/WebView가 이미 있는 환경이므로 필수 구성이 없는 새 PC까지 확인한 결과는 아니다.

## 대용량 실제 검사

`scripts/desktop/smoke-embedded-large-import.mjs`로 새 테스트 프로필에서 실행했다. fixture는 압축하지 않은 ZIP 안에 유효한 4096×4096 PNG 11페이지를 넣은 합성 파일이다. 여러 실제 작품/포맷의 최대치를 보장하는 검사는 아니다.

- 입력: **554,582,512 bytes (약 529MiB)**.
- 공통 가져오기 화면에서 중간 숫자 퍼센트 확인 → 창을 닫고 서버 처리 지속 → 책장에서 이미지 리더 열기 → 원본 다운로드 해시 일치.
- 서버 저장 완료까지 **78,572ms**, 이미지 표시와 원본 해시 검사까지 **93,980ms**. 초기 서버 준비 시간 포함.
- 2초 간격 표본에서 관리 중 서버 PID들의 RSS 합계 최대 **989,696,000 bytes (약 944MiB)**. 브라우저와 PostgreSQL 추가 자식 프로세스는 제외하므로 앱 전체 최대 메모리로 표시하지 않는다.
- 프로필 크기 표본 최대 **2,315,906,104 bytes (약 2.16GiB)**. 초기 DB 포함, 외부 fixture 제외. 작업 임시 공간을 포함한 전체 프로필 수치이며 임시 파일만의 최고치가 아니다. 완료 후에는 원본과 이미지 자산을 보관한다.
- 실제 실패를 재현한 수정: 업로드 초기화는 만화 최대 4GiB를 허용했지만 청크 수신은 500MiB만 허용했다. 같은 파일/가져오기 모드별 제한을 사용하도록 공통 서버를 수정했다.

## 다음 완료 조건

1. Windows 설치·복구 검사는 통과했다. 새 PC 필수 런타임 미설치 조건과 재배포 조건을 확인한다.
2. 주석과 백업 저장 UI, 소스 실행 주체를 실제 앱에서 검사한다. EPUB/PDF는 공통 브라우저 검사를 통과했으며 native WebView 경로는 추가 확인 대상이다.
3. 기존 로컬 백업 → 서버 변환은 별도 로컬 저장 구조 없이 복사·검증·전환한다.
4. 이후 같은 서재 접속과 독립 서재 동기화를 구분해 P3를 진행한다.
