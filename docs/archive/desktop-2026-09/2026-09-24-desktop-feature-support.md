## 대용량 실제 검사

`scripts/desktop/smoke-embedded-large-import.mjs`로 새 테스트 프로필에서 실행했다. fixture는 압축하지 않은 ZIP 안에 유효한 4096×4096 PNG 11페이지를 넣은 합성 파일이다. 여러 실제 작품/포맷의 최대치를 보장하는 검사는 아니다.

- 입력: **554,582,512 bytes (약 529MiB)**.
- 공통 가져오기 화면에서 중간 숫자 퍼센트 확인 → 창을 닫고 서버 처리 지속 → 책장에서 이미지 리더 열기 → 원본 다운로드 해시 일치.
- 서버 저장 완료까지 **78,572ms**, 이미지 표시와 원본 해시 검사까지 **93,980ms**. 초기 서버 준비 시간 포함.
- 2초 간격 표본에서 관리 중 서버 PID들의 RSS 합계 최대 **989,696,000 bytes (약 944MiB)**. 브라우저와 PostgreSQL 추가 자식 프로세스는 제외하므로 앱 전체 최대 메모리로 표시하지 않는다.
- 프로필 크기 표본 최대 **2,315,906,104 bytes (약 2.16GiB)**. 초기 DB 포함, 외부 fixture 제외. 작업 임시 공간을 포함한 전체 프로필 수치이며 임시 파일만의 최고치가 아니다. 완료 후에는 원본과 이미지 자산을 보관한다.
- 실제 실패를 재현한 수정: 업로드 초기화는 만화 최대 4GiB를 허용했지만 청크 수신은 500MiB만 허용했다. 같은 파일/가져오기 모드별 제한을 사용하도록 공통 서버를 수정했다.
