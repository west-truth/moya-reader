# 저장공간 설정 통합

## 목표와 범위

설정에 **저장공간**을 독립 분류로 추가한다. 로컬 파일과 소스 다운로드를 함께 관리하고, 백업·복원을 이곳으로 옮긴다. 콘텐츠 소스에는 다운로드·자동 삭제 바로가기를 유지한다. 자동 삭제 정책은 기존 구현을 그대로 사용한다.

이번 작업은 기존 원본 다운로드·대용량 백업 작업 위에서 진행한다. 서비스 배포와 운영 데이터 정리는 수행하지 않는다.

## 화면 구성

1. 사용량 요약: 서버 연결 시 서버의 보관 파일 용량, 기기에서는 브라우저 사용량을 구분한다. 작품 수·휴지통 용량과 새로고침, 작품별 관리 진입 버튼을 제공한다.
2. 간편 정리: 읽은 회차의 기존 미리보기·확인 후 정리 동작을 재사용한다. 로컬 원본·즐겨찾기·미독·현재 읽는 회차는 자동 정리 대상이 아니다.
3. 백업과 복원: 기존 스트리밍 백업/검사/복원 화면으로 이동한다. 동기화 화면에는 연결과 동기화만 남긴다.
4. 소스 다운로드: 접을 수 있는 하단 영역에 미리 받기·대기열 복구·읽은 회차 자동 정리 옵션을 둔다. 소스 설정의 바로가기는 이 영역을 펼쳐 바로 보여준다.
5. 작품별 관리: 별도 화면에 제목 검색, 용량/이름 순, 책장/휴지통 분류와 선택 작업을 제공한다. 책장에서는 휴지통 이동, 휴지통에서는 복원·명시적 영구 삭제를 제공한다. 모바일에서도 배경 설정과 이중으로 스크롤하지 않게 한다.

## 집계와 삭제 원칙

- 파일 본문·S3 버킷·전체 디스크를 스캔하지 않고 기존 자산 메타데이터를 읽는다. 현재 참조하는 원본과 활성 자산을 집계한다. DB·캐시·임시 파일·이전 리비전은 별도이며 서버 디스크 전체 사용량으로 표현하지 않는다.
- 같은 저장 파일은 요약에서 한 번만 센다. 책장과 휴지통이 파일을 공유하면 책장에 귀속한다. 작품별 합계는 공유 파일 때문에 전체 합계보다 클 수 있고 삭제 후 즉시 확보할 용량을 보장하지 않는다.
- 로컬 모드도 Blob 본문을 읽지 않고 IndexedDB 자산 메타데이터로 계산한다. 브라우저 전체 추정 사용량과 작품 파일 합계는 별도 표시한다.
- 작품 목록은 메타데이터만 조회하며 화면에는 50개씩 표시한다. 새 인덱싱 서비스·주기적 스캔·정리 작업자를 추가하지 않는다.
- 삭제는 기존 catalog 저장소의 휴지통/복원/영구 삭제를 사용한다. 선택 항목과 메타데이터 리비전을 확인한다. 독서·가져오기·다운로드 중에는 관리 삭제를 막는다. 조회 실패를 0으로 표시하지 않는다.
- 원본 자동 삭제, 고아 파일 삭제, 전체 브라우저 데이터 삭제, 다운로드 정책 변경은 하지 않는다.

## 검증 범위

공유 파일 중복 제거, 휴지통 귀속, 사용자 범위, 로컬 메타데이터 조회, 선택한 작품만 처리되는지와 오류/진행 상태를 확인한다. 기존 보존 규칙은 관련 retention 테스트로 확인한다. 전체 플랫폼·확장·대용량 백업 테스트를 반복하지 않는다.

## 구현 결과 (2026-09-22)

- 저장공간 분류를 추가하고 백업·복원을 동기화 분류에서 이동했다. 기존 `downloads` 진입값도 저장공간의 다운로드 영역으로 연결한다. 콘텐츠 소스 바로가기는 영역을 펼치고 해당 위치로 이동한다.
- 인증된 `GET /api/storage/usage`는 한 SQL 스냅샷으로 현재 계정의 원본/활성 자산을 집계한다. 파일 본문이나 운영 버킷은 읽지 않는다. 로컬은 `novels`/`book_assets` 메타데이터를 동일한 readonly 트랜잭션에서 읽고 Blob 저장소는 읽지 않는다.
- 요약의 휴지통 용량은 **휴지통에서만 참조하는 파일**이다. 책장과 공유하는 파일은 책장에 포함한다. 작품 목록에서는 해당 작품의 전체 파일 크기를 표시한다.
- 작품별 관리는 설정 안의 별도 하위 화면이다. 용량/이름 정렬, 검색, 50개씩 더 보기, 선택 휴지통 이동, 복원, 영구 삭제를 제공한다. 기존 리비전 검사를 사용하며 부분 실패도 완료/미처리를 나눠 알리고 목록을 갱신한다. 처리 중에는 설정 닫기와 탭 전환을 막아 삭제 작업이 숨지 않게 했다.
- 간편 정리는 기존 다운로드 보존 규칙과 확인창을 재사용한다. 자동 정리의 기본값과 서버 공유 범위는 변경하지 않았다. 원본을 자동 삭제하는 기능은 추가하지 않았다.

## 확인 결과

- 관련 Vitest **6개 파일·13개 테스트 통과**: 공유 파일/휴지통 집계, Blob 없는 로컬 조회, API 인증, 선택/리비전/부분 실패/확인 취소/독서 중 차단, 설정 이동, 기존 회차 보존 규칙.
- 격리 PostgreSQL 확인: 2GiB 초과 파일, 원본과 자산의 같은 키 중복, 책장/휴지통 공유, 다른 계정 제외, staged/superseded 제외, 빈 책장 모두 통과. 임시 테이블·스키마만 사용하고 종료 시 제거했다.
- 기존 `scripts/performance/settings-ux-smoke.mjs`를 갱신했다. 360/390/768/1366px 설정 탐색, 소스 바로가기, 360/390/1366px 저장공간/작품 관리/휴지통 이동/복원을 확인했다. 라이트·다크 테마와 긴 제목의 가로 넘침을 확인했다. 별도 운영 데이터 없이 fixture로 실행했다.
- 웹·서버 타입 검사, 변경 TS/TSX/스크립트 lint, CSS 검사, diff 공백 검사 통과. 전체 플랫폼/확장/백업 부하 검사는 반복하지 않았다.

## 용량 해석과 한계

표시값은 현재 책장·휴지통이 참조하는 **파일 메타데이터 합계**다. 서버 디스크 전체 사용량·여유 용량, DB, 표지/목록 캐시, 가져오기·백업 임시 파일, 이전 리비전은 포함하지 않는다. 브라우저 전체 추정치는 이 합계와 더하지 않는다. 캐시 전체 비우기나 고아 파일 청소는 추가하지 않았다.

휴지통 이동만으로 공간은 확보되지 않는다. 영구 삭제 후에도 다른 참조가 남은 파일은 유지되고, 서버의 기존 정리 대기열에 따라 반영이 지연될 수 있다. 운영 데이터 삭제·서비스 배포는 수행하지 않았다.

## 후속 UI 정리

- 초기 화면의 ‘아주 긴 제목의 로컬 합본 작품 파일’은 브라우저 fixture의 가상 작품명이었다. 제품 고정 문구가 아니며 예시 이름을 자연스러운 가상 제목으로 변경했다.
- 사용량 카드 안에 전체 용량과 책장/휴지통 구성을 묶었다. 구성 막대는 디스크 점유율이 아니며, 두 범주의 파일 용량 비율만 표시한다. 집계 설명과 기기 사용량은 펼쳐 확인한다.
- 휴지통 요약에서 바로 관리 화면으로 이동한다. 작품별 관리는 책장/휴지통 전환 버튼, 검색, 정렬, 선택 상태 강조를 제공한다. 선택하지 않은 상태의 비활성 작업 버튼은 숨기고 선택 시 하단에 작업 표시줄을 표시한다.
- 백업 진입을 한 줄 메뉴로 줄이고 테마 색상과 간격을 정리했다. 저장/삭제 정책과 API에는 변경이 없다.
- 관련 컴포넌트 테스트 6개, 웹 타입 검사, 변경 파일 lint, 기존 설정 브라우저 검사(모바일·PC, 라이트·다크, 휴지통 이동·복원)를 확인했다.
