# 대용량 로컬 회차 추가 및 EPUB 중복 읽기 개선

## 범위

기존 `fix/long-source-download-compact-cards` 브랜치에서 구현하고 단일 PR로 묶는다. 운영 데이터/컨테이너는 변경하지 않는다. Self-host에서 일반 EPUB·ZIP·CBZ 파일을 기존 같은 형식 작품에 추가한다. 파일당 4GiB, 기존 개별 항목/압축 해제 제한을 유지한다. 텍스트·RAR·7z·중첩 백업 등 다른 경로의 한도를 일괄 확대하지 않는다.

## 확인한 제약

- 기존 만화 증분 경로는 원본 목록과 자산 재사용 구조가 있지만 기반 원본 읽기, source_part 저장, 클라이언트 회차 파일 생성에 전체 바이트 적재가 남아 있다.
- 기존 EPUB 회차 병합은 브라우저가 기존 원본과 새 파일을 분석하고 다시 묶는다. 수 GiB에 적용하면 서버에서 메모리를 줄인 효과가 사라진다.
- EPUB 단일 가져오기는 이미지의 해시 조사와 저장을 위해 두 번 읽는다. 저장 콜백을 제공하는 hosted 경로에서 읽기·해시·저장을 한 번에 처리하되 기존 식별자와 실패 정리를 유지할 수 있다.

## 단계 및 완료 조건

- [x] 1. EPUB 한 번 읽기: hosted 이미지 저장 콜백, 동일 본문/이미지 ID, 중간 실패 정리 및 실측 비교.
- [x] 2. 서버 회차 추가: 원본 파일 그대로 청크 업로드, 기존 내용/자산 재사용, 회차/문단/페이지 ID 충돌 방지, 파일별 원본 보존.
- [x] 3. UI 연결: 기존 회차 추가 메뉴에서 지원, 브라우저가 기존 수 GiB 원본을 내려받거나 재압축하지 않음. 순차 추가 및 기존 백그라운드 상태/취소 UI 재사용.
- [x] 4. 호환 경로 확인: 첫 추가와 반복 추가, 같은 파일 재시도, 기준 revision 충돌, 읽기 위치/읽음 표시/표지/제목 보존, 원본 참조와 삭제/내보내기 경계 확인.
- [x] 5. 격리 DB/S3에서 실제 대용량 EPUB·CBZ 추가 및 재조회. 기존 자산 불필요한 재쓰기와 RAM 증가가 없는지 확인. 관련 테스트·타입 검사만 실행하고 결과/제한 기록.

각 단계 완료 시 이 문서를 갱신하고 커밋한다. 저장 형식과 적용 방식은 실제 기존 코드의 재사용 가능 범위를 확인해 기록한다. 지원되지 않는 경로를 지원 완료로 표현하지 않는다.

## 진행 기록

- EPUB hosted 파서에 저장 콜백을 연결했다. 이미지 한 장의 해시 계산 직후 S3에 저장하고 바이트를 해제한다. 기존 generator 소비자는 종전 경로를 유지한다. 기존 본문·이미지·표지 ID 동일성 및 저장 콜백 실패 중단을 포함한 39개 관련 테스트와 서버 타입 검사를 통과했다. 대용량 시간/RSS 비교는 마지막 격리 검사에서 함께 수행한다.

- 서버에 `append_local_archive` 모드를 추가했다. 기존 회차 추가 메뉴에서 일반 EPUB·ZIP·CBZ 원본을 파일 이름의 자연 정렬(2권 → 10권) 순서로 업로드한다. 이전 원본을 브라우저에서 내려받거나 재압축하지 않는다. 회차 하나가 실패하면 뒤 파일은 중단하고 다시 시도할 수 있다.
- 기존 DB 본문과 자산 키를 유지하고 새 회차만 추가한다. 새 회차/문단 ID에는 작품 ID와 원본 해시를 포함한다. 첫 추가 때 기존 원본을 S3 내부 복사로 보존하고 이후에는 기존 원본을 읽거나 복사하지 않는다. 활성 원본은 작은 JSON 목록, 실제 원본은 개별 `source_part`다. 합산 파일 크기는 4GiB로 제한하지 않으며 개별 업로드만 4GiB 제한을 적용한다. 만화는 작품당 20,000페이지, 원본 목록은 2,000개까지다.
- 같은 원본 해시는 재업로드해도 무변경 완료한다. 같은 이름의 다른 내용은 혼동을 막기 위해 거절한다. 현재 revision 확인과 기존 advisory lock/실행권한/트랜잭션/객체 정리 경로를 재사용한다.
- 격리 PostgreSQL + S3 HTTP 검사에서 EPUB·CBZ의 첫 추가와 반복 추가, 같은 파일 재시도, 오래된 revision 거절, 취소 후 기존 데이터 유지, 제목/표지/북마크/읽기 위치/읽음 표시 유지, 원본 파일 보존, 작은 합본의 서버 백업/복원을 확인했다. 브라우저 controller 검사에서는 2GiB로 표시한 File의 전체 읽기와 이전 원본 다운로드 없이 순차 업로드되는 것을 확인했다(실제 바이트 크기 검사는 아래 Docker 실측으로 별도 수행).

## 호환 경계

- 기존 회차의 읽기·제목 수정·읽음 표시는 유지된다. 합본을 TXT처럼 다시 해석하는 본문 분할/병합은 차단한다.
- 일반 파일 다운로드는 합친 EPUB/CBZ 재생성이 아니라 **순서별 원본 파일 ZIP**으로 제공한다. 브라우저가 결과 Blob을 보관하는 경로라 합계 500MiB까지만 허용하고 그 이상은 파일을 읽기 전에 안내한다. 이 ZIP은 원본 보관용이며 하나의 작품으로 자동 복원하는 별도 포맷이 아니다.
- Cloud Vault의 새 합본 원본 전송/복원은 아직 지원하지 않는다. JSON 목록만 전송해 백업된 것처럼 보이지 않도록 명시적으로 실패를 보고한다. 같은 self-host 서버에 연결한 기기 간 작품 조회는 그대로 동작한다.
- 앱의 전체 서버 백업은 기존 512MiB/1,000항목 제한을 유지한다. 작은 합본의 원본·본문·이미지 복원은 검사했지만 수 GiB 합본을 앱 백업으로 복원할 수 있다는 뜻은 아니다. 수 GiB 데이터의 운영 백업은 DB와 객체 저장소를 함께 보관하는 운영자 백업이 필요하다.
- 소스 다운로드 회차의 자동 삭제/기존 delta 추가는 기존 형식을 유지한다. 새 저장 방식은 로컬 원본 추가용이다. 새로운 합본에 과거 comic delta를 보내면 잘못 재해석하지 않고 안내한다. 수 GiB 원본 내보내기·Cloud Vault·합본 회차 개별 삭제까지 범위를 넓히지 않는다.

## 대용량 실측

별도 PostgreSQL·MinIO와 `--memory=1g --memory-swap=1g` worker에서 실행. 시간은 청크 준비 후 worker 처리 완료까지이며 업로드 전송 시간은 제외한다.

| 작업                  |                           원본 크기 | 처리 시간 | 프로세스 최대 RSS |
| --------------------- | ----------------------------------: | --------: | ----------------: |
| EPUB 처음 가져오기    |  1,134,493,182bytes (1.06GiB), 90장 |    23.9초 |            228MiB |
| 같은 작품에 EPUB 추가 |          위와 같은 크기의 별도 원본 |    25.8초 |            235MiB |
| CBZ 처음 가져오기     | 2,268,967,842bytes (2.11GiB), 180장 |    43.4초 |            282MiB |
| 같은 작품에 CBZ 추가  |          위와 같은 크기의 별도 원본 |   174.1초 |            285MiB |

EPUB 합본은 원본 합계 약 2.11GiB, 이전 이미지/표지 91개와 본문 ID를 유지했다. 같은 형태의 이전 두 번 읽기 측정(35.3초/281MiB)보다 개선됐으나 서로 다른 실행 시점의 참고 비교이며 보장 속도가 아니다. cgroup 최고 사용량에는 디스크 페이지 캐시가 포함되어 약 1GiB에 도달했다. RSS와 컨테이너 전체 사용량은 구분한다. 4GiB 단일 파일의 실제 처리 검사는 이번에도 수행하지 않았다.

CBZ 합본은 원본 합계 약 4.23GiB/360페이지다. 첫 180페이지 및 표지의 자산 키와 기존 회차 ID를 모두 유지했고, 원본 두 파일의 S3 크기와 앞뒤 이미지 디코딩을 확인했다. 첫 추가는 기존 원본의 안전한 보존 복사도 포함한다. 이 실행에서는 앞선 실행보다 조립·저장 단계 시간이 늘어 조립/해시 30.0초, 원본 보존+새 원본 저장 67.2초, 새 이미지 저장 76.1초로 측정됐다. 따라서 회차 추가가 항상 단독 가져오기보다 빠르다는 주장은 하지 않는다. 파일 크기에 비례하는 RAM 적재와 기존 본문/이미지 재처리를 제거한 것이 핵심이다. 후속 실행을 구분해 볼 수 있도록 원본 보존을 별도 측정 단계로 분리했다.

EPUB 내부 파일명이 겹쳐도 이전 권의 각주/링크로 이동하지 않도록 새 회차의 내부 href에 원본 식별자를 붙였다. 외부 링크는 유지한다. 동일 경로/같은 제목 EPUB을 이용해 링크/각주 대상 일치를 확인했다.

검증은 관련 단위·통합 검사와 타입/lint로 한정한다. 기존 `test:import-pages`에 새 회차 추가/원본 내보내기 검사만 포함하며, 수 GiB 검사 자체는 opt-in 수동 검사로 유지한다. 전체 플랫폼 테스트나 새 CI job을 추가하지 않았다.

## 최종 확인

- 새 회차 추가 통합 검사(EPUB·CBZ), 파일 순서/실패 중단 UI 검사, 원본 내보내기 검사 통과. 기존 업로드·가져오기·API 계약 관련 검사도 통과했다.
- 만화의 첫 권 변환 시 전체 페이지가 읽음인 경우 권 단위 읽음 표시로 이어지는지 실제 조회 결과로 확인했다. 일부만 읽은 권을 전체 읽음으로 바꾸지는 않는다.
- 웹·서버·스크립트 타입 검사, 변경 코드 lint/format, 공유 패키지 경계 검사, 웹·서버 production build와 웹 산출물 검사를 통과했다.
- 대용량 검사용 PostgreSQL·MinIO·worker와 네트워크는 정리했다. 운영 데이터와 서비스는 변경하지 않았다.
