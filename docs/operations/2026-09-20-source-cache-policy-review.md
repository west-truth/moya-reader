# 탐색·작품 상세·회차 목록 캐시 정책 검토

최초 검토 기준: `1fefe05` (PR #56 작업 브랜치). 검토 후 사용자 승인에 따라 같은 브랜치에 구현했다. 아래 검토 당시 상태와 제안을 보존하며, 실제 구현 범위와 검증은 마지막 절에 기록한다. 운영 서비스에는 아직 배포하지 않았다.

## 결론

목록, 작품 상세, 회차 목록은 더 적극적으로 재사용하는 것이 적절하다. 우선순위는 TTL 숫자를 늘리는 것보다 **저장된 내용을 바로 표시하고, 필요한 경우에만 뒤에서 갱신하는 흐름을 일관되게 만드는 것**이다. 방문했던 작품과 탭을 왕복할 때의 대기, 일시적인 외부 사이트 장애가 특히 줄어든다.

캐시는 첫 방문의 느린 원본 응답, 이미지 디코딩, 스크롤/레이아웃 결함까지 해결하지는 않는다. 보관량은 메타데이터와 이미지를 구분한다. 이전 실측의 TOTAL 토끼 표지 1개는 3,345,480B였으므로 원본 표지 100개가 모두 이 크기라면 약 319MiB다. 작은 JSON이라고 해도 회차가 수만 개이거나 소스가 많으면 합산 상한이 필요하다.

또한 TTL은 ‘다시 확인할 시점’이지 파일이나 IndexedDB 레코드의 자동 삭제 시점이 아니다. 메모리 캐시도 살아 있는 서버 프로세스에서는 종료 전까지 남을 수 있다. 신선도, 오래된 결과를 보여줄 수 있는 기간, 실제 제거 조건을 분리한다.

| 데이터              | 원본 재확인 없이 재사용 | 오래된 결과를 먼저 표시할 수 있는 최대 나이 | 갱신 방식                                                                      |

예: 어제 읽은 작품을 오늘 열면 소개와 회차를 바로 보여주면서 현재 회차를 확인한다. 새 회차가 있으면 추가하고, 갱신이 실패해도 기존 목록을 지우지 않는다. 위 ‘최대 나이’는 마지막 원본 성공 확인 시각부터 계산한다. 캐시에서 읽었다고 새 데이터처럼 시간을 연장하지 않는다.

일정 시간마다 모든 소스를 갱신하는 polling은 하지 않는다. 보이는 화면의 진입/복귀를 기준으로 하고 같은 요청은 병합한다. 서버에서 원본을 확인한 시각을 응답에 포함해, 브라우저가 서버의 오래된 결과를 새것으로 다시 30분 보관하는 식의 만료 누적을 막는다.

## 용량과 저장 위치

1차 구현은 기존 메모리·IndexedDB를 활용한다. Redis 추가, 이미지 원본의 영구 디스크 캐시, 사용자에게 여러 캐시 숫자를 조절하게 하는 새 설정 페이지는 필요하지 않다.

| 위치                          | 제안 예산                                      | 의미                                                                                            |
| ----------------------------- | ---------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| 서버 표지 메모리              | 프로세스 합계 128MiB, 계정당 최대 64MiB        | 계정별 격리는 유지하되 합계 예산도 적용. 항목 수도 프로세스 1,000/계정 500으로 제한             |
| 서버 목록·상세·회차 JSON      | 프로세스 합계 32MiB, 계정당 최대 16MiB         | 최대 1,000키. 여러 종류의 메타데이터가 같은 총예산 사용                                         |
| 브라우저 메모리               | 표지 32MiB + 메타데이터 8MiB 목표 유지         | 우선 TTL·재사용 순서 개선. 모바일 RAM 사용을 무작정 늘리지 않음                                 |
| 브라우저 IndexedDB 메타데이터 | origin 전체 최대 32MiB, 최대 1,000키, 최대 7일 | 기존 저장소 확장. 계정/서버별 분리와 로그아웃 정리. 검색은 최대 6시간 등 위의 더 짧은 한계 우선 |

서버 제안 예산 합계는 캐시 payload 기준 160MiB다. 객체/Map/Blob·진행 중 응답·브라우저 이미지 디코딩 메모리는 별도이므로 프로세스 RAM의 절대 상한이라는 뜻은 아니다. 다중 서버 프로세스를 띄우면 프로세스 수만큼 늘 수 있다.

직렬화된 목록 1,000개 항목이 항목당 1KiB라면 약 1MiB, 회차 10,000개가 항목당 300B라면 약 2.9MiB다. 이는 예시 계산이며 실측 평균이 아니다. 한 번 읽을 때 실제 크기를 집계해 바이트 예산에 반영한다. 예산보다 큰 결과는 사용은 가능하되 캐시에 넣지 않거나 필요한 페이지만 저장한다.

삭제는 캐시 쓰기/기동 시 제한된 수량만 정리한다. 메타데이터의 마지막 열람 시각과 원본 확인 시각은 별도로 관리한다. 저장 공간 오류가 나면 화면 요청은 성공시키고 메모리 캐시로 계속 사용할 수 있어야 한다.

**서버의 `references/*.json`은 일반 캐시로 일괄 삭제하지 않는다.** 설치된 확장·라이브러리·다운로드가 참조하는 원본 URL 복원에 쓰인다. 표시용 결과 캐시의 용량 관리와 분리하며, 이 작업에서 archive/orphan 청소를 확장하지 않는다. 다운로드된 책·읽기 기록 역시 캐시 제거 대상이 아니다.

## UI 및 정확성 조건

- 저장된 제목·표지·목록을 즉시 표시하고 갱신은 작은 표시로 안내. 화면 전체 로딩 전환·기존 카드 제거 금지.
- 정상 캐시 히트마다 설명 문구를 붙이지 않는다. 실패 시에만 ‘저장된 목록 · 다시 시도’ 정도로 짧게 표시.
- 새 목록은 현재 선택과 스크롤을 보존한다. 회차 갱신 시 작품/회차 ID로 읽음·다운로드 상태를 다시 합치며, 오래된 UI 상태를 통째로 복원하지 않는다.
- 앞 페이지 갱신 결과와 이전 스냅샷의 다음 페이지를 섞지 않는다. `snapshotId` 또는 목록 세대에 커서를 묶고, 갱신 반영 시 뒤 페이지를 폐기·재조회한다. 회차도 하나의 정렬된 스냅샷을 사용한다.
- 현재 브라우저 표지 키는 소스·세대·작품 ID 기준이며 Blob 자체에는 TTL이 없다. 서버 TTL만 늘리거나 줄여서는 같은 세션의 표지 교체가 반영되지 않을 수 있다. 표지 revision 또는 재검증 시각을 연결하고, 새 표지가 준비될 때만 기존 Blob을 교체한다.
- 명시적 새로고침은 브라우저 → 서버 → 호환 어댑터 캐시까지 실제 원본 재확인을 전달한다. 캐시 모드는 호스트 전용 요청 옵션으로 두고 각 확장 개발자가 구현하도록 떠넘기지 않는다. 구형 클라이언트는 기존 기본 동작 유지.
- 계정/서버/소스/로그인·설정 세대/작품/검색·필터·정렬·페이지를 키에 반영. 현재 IndexedDB 키에는 세대 필드가 없으므로 추가 또는 세대별 명시적 무효화 필요. 로그인 변경·소스 비활성화 후 이전 계정 결과를 보여주지 않는다.
- 502·일시적인 네트워크 실패에는 허용 기간 내 성공 캐시를 유지한다. 인증/권한 실패나 명확한 삭제 응답을 정상 상태로 덮지 않는다. 원본 HTML 오류 페이지는 결과 캐시로 저장하지 않는다. 현재 브라우저 표지의 30초 실패 캐시는 자동 반복 요청 방지에만 사용하고, 명시적인 다시 시도는 이를 우회하도록 한다.
- 회차 목록은 표시용으로 재사용하되 다운로드 시작/실패 복구는 현재 연결과 유효한 원본 참조를 사용한다. 캐시 목록만 보고 회차 삭제·다운로드 정리를 실행하지 않는다.
- 서명된 표지 URL의 유효기간이 더 짧으면 그 기간을 우선하고 필요 시 새 URL을 조회한다. 인증 응답을 공용 `public` HTTP 캐시로 바꾸지 않는다.

## 구현 순서

1. **체감 개선과 갱신 정확성**: 둘러보기의 지속적인 강제 갱신 조건 수정, 일반 목록·부분 회차도 캐시 먼저 표시, 명시적 갱신 옵션을 서버까지 연결, 세대별 무효화/원본 확인 시각 전달.
2. **보관 확대**: 위 종류별 TTL·오래된 결과 허용 정책 적용. 기존 IndexedDB에 바이트/개수/수명 관리 추가. 서버 메타데이터 캐시는 호스트의 조회 경계에 두고 Mangayomi/APK/moyaext가 공통 정책을 쓰도록 한다. 기존 어댑터 내부 캐시와 중복 저장하지 않도록 책임 분리.
3. **표지 예산 확대**: 서버 24시간 정책과 합계/계정 예산 적용. 큰 원본의 최초 비용은 후속 썸네일 검토 대상으로 유지.
4. **선택적 미리 받기**: 위 단계로도 필요한 경우 현재 탭의 다음 페이지 1개·곧 보일 표지만 낮은 우선순위로 조회. 사용자 요청 우선, 탭 이동 시 취소, 현재 전역/소스별 동시성 제한 유지. 모든 소스/회차 일괄 조회 금지.

필수 검증만 진행한다: 재진입 즉시 표시/요청 수, 수동 갱신의 원본 도달, 원본 장애 시 캐시 유지, 새 회차 반영·스크롤 유지, 계정/설정 변경 격리, 예산 초과 제거, 페이지 스냅샷 혼합 방지. 변경 없는 플랫폼 전체 검사를 반복하지 않는다.

## 구현 결과 — 2026-09-20

### 적용한 흐름

- `cache-policy.ts`에서 인기 30분/24시간, 최신 2분/24시간, 검색·필터 10분/6시간, 회차 2분/7일을 통일했다. 작품 상세는 6시간/7일, 필터 정의는 6시간/7일이다. 앞 숫자는 재확인 없이 사용하는 시간, 뒤 숫자는 성공 결과의 보관 한계다.
- 탐색 홈·고정 소스·기존 소스 화면이 저장된 목록을 먼저 표시한다. 탐색도 IndexedDB를 사용해 문서를 다시 연 뒤 결과를 복원한다. 메모리·디스크를 거쳐도 메타데이터의 원본 확인 시각을 보존한다. 작품 카드에서 진입하면 제목·표지도 먼저 표시한다.
- 오래된 목록을 표시한 상태에서 재조회한다. 둘러보기는 기존 `새 목록 보기`, 전체 회차는 기존 갱신 적용 흐름을 사용한다. 일시적인 서버 오류에는 이전 성공 결과를 유지하고, 실패 응답 자체를 성공 캐시로 저장하지 않는다. 읽음·다운로드 상태는 현재 로컬 상태와 다시 합친다. 서버가 오래된 결과를 돌려준 경우 구독의 최신 확인 결과로 기록하지 않는다.
- `cacheMode: reload`를 호스트 요청 옵션으로 연결했다. 수동 갱신·새 회차 확인·다운로드 이어받기는 회차·상세의 어댑터 캐시도 우회한다. 진행 중인 같은 원본 요청은 공유하며, 개별 화면 취소가 다른 소비자의 요청을 끊지 않는다. 목록 TTL 만료는 표지 캐시를 비우지 않고, 명시적 갱신만 별도 `refreshCovers` 옵션으로 표지도 갱신한다. 확장 게스트 API에는 새 옵션을 노출하지 않는다.
- 서버의 목록 커서를 소스·설정 세대·검색/필터 조건·첫 페이지 스냅샷에 묶었다. 호환 어댑터의 회차 커서도 파일 스냅샷에 묶어, 오래 걸린 다음 페이지 조회 중 회차 TTL이 지나도 같은 목록을 사용한다. 다른 갱신이 먼저 완료되면 혼합해서 붙이지 않고 새로고침을 안내한다. 무효가 된 커서의 재시도는 첫 페이지부터 갱신한다.
- 소스·계정·서버 범위와 연결 세대로 캐시 키를 나눈다. 소스 목록만 새로 읽고 세대가 그대로이면 유효 캐시를 지우지 않는다. 로그아웃은 메타데이터 캐시만 정리한다.

### 실제 저장 한계

- Mangayomi/APK 표지: 24시간 재사용, 일시적 오류 시 최대 7일 이전 성공 결과 사용. 프로세스 합계 **128MiB/1,000개**, 계정별 **64MiB/500개**의 공통 예산이다.
- 설치 소스 목록·상세·회차 JSON: 프로세스 합계 **32MiB/1,000키**, 계정별 **16MiB**. 모든 패키지 형식이 같은 예산을 사용한다.
- 탐색 메모리: **8MiB/1,000키**. 브라우저 표지: **32MiB/200개 목표**, 24시간 후 다음 조회에서 재검증. 화면에서 사용하는 기존 Blob은 교체·퇴거 때문에 끊기지 않게 보호하므로 순간적으로 목표를 넘을 수 있다.
- IndexedDB: origin 전체 **32MiB/1,000키**, 종류별 보관 한계 및 절대 최대 7일. 쓰기 시 전체 만료/LRU 정리, 읽기 시 해당 만료 항목 제거. 별도 타이머나 기동 스캔을 추가하지 않았으므로 앱을 쓰지 않는 동안 정확히 7일째 물리 삭제되는 방식은 아니다. 다시 읽으면 만료 결과를 반환하지 않는다.
- Blob URL과 알려진 서명/토큰 쿼리가 있는 표지 URL은 디스크에 보관하지 않는다. `coverRef`로 다시 해결할 수 없는 임시 표지는 목록 복원 후 재조회한다. 직접 접근 가능한 일반 표지 URL은 유지한다. 서명 방식 전체의 만료 시간을 추측하는 파서는 추가하지 않았다.
- 다운로드 파일, 라이브러리, 읽기 기록, 서버의 영구 원본 URL 참조 파일은 캐시 정리에서 제외했다. 저장 공간 오류 때문에 성공한 목록 조회를 실패 처리하지 않는다.

### 범위와 남은 선택 사항

- 설치 소스의 공통 `SourceWork` 계약에 신뢰할 만한 완결 상태가 없으므로 회차는 보수적으로 **2분**을 쓴다. 완결을 추측해 6시간으로 늘리지 않았다.
- 다음 페이지 선행 로딩과 이미지 썸네일 변환은 추가하지 않았다. 기존 화면 근처 표지 로딩과 요청 수 제한을 유지한다. 첫 방문의 원본 사이트 지연·큰 이미지 전송/디코딩은 별개다.
- 브라우저에 저장된 내용이 있는 재진입이 즉시 표시되는 대상이다. 서버에만 만료 데이터가 있고 브라우저에는 없는 첫 진입은 원본 재확인을 기다릴 수 있다. 주기적인 전체 소스 갱신이나 브라우저 탭 복귀만을 위한 새 polling은 없다.
- 서버 재시작/퇴거로 페이지 스냅샷이 사라지면 보관된 첫 페이지는 표시할 수 있지만 더 불러오기는 새로고침이 필요할 수 있다. 잘못된 페이지를 이어 붙이는 대신 명시적 갱신으로 복구한다.
