# 탐색 홈·사용자 지정 탭·사이드 메뉴 UX 계획

작성: 2026-09-20 · 상태: **검토 및 구현 계획, 제품 구현 전**

기준: `d3153f3` (`docs/settings-ux-plan`, 설정 UX PR #52의 코드 포함).
계획 브랜치: `docs/discovery-ux-plan`. 기존 설정 작업 위에서 검토했으며, 별도 구현을 시작할 때 PR #52 병합 상태에 맞춰 기준을 갱신한다.

## 1. 결론과 범위

구현할 가치가 있고 기존 소스 계약을 상당 부분 재사용할 수 있다. 단일 소스 목록을 크게 꾸미는 수준에서 끝내지 않고, **사용자가 구성한 탐색 홈 → 소스별 목록 → 작품 상세 → 읽기/다운로드**로 이어지는 화면을 만든다.

- 라이브러리·책장·소스 사이드 메뉴를 각각 접고 펼친다.
- `탐색`을 라이브러리와 나란한 주 탐색 경로로 추가한다.
- 탐색 안에 `만화`, `소설`, `웹툰` 같은 사용자 지정 탭을 만들고, 각 탭에 소스와 노출할 목록을 배치한다.
- 최신·인기·분류는 해당 소스가 실제 제공하는 기능만 표시한다.
- 같은 탭 세션에서 목록·표지를 재사용하고, 뒤로 가기 시 읽던 목록과 위치를 복원한다.
- 상용 앱 수준의 경험은 배너 수보다 **응답성, 탐색 연속성, 실패 복구, 조작의 예측 가능성**으로 판단한다.

이번 문서는 코드 검토 결과와 설계 제안이다. 실제 소스의 최신/인기 결과나 새 화면의 성능을 검증 완료했다고 의미하지 않는다. 운영 서비스·데이터는 변경하지 않는다.

## 2. 현재 구현에서 확인한 기반과 한계

| 영역        | 확인한 구현                                                                                                            | 이번 작업의 판단                                                                       |
| ----------- | ---------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 사이드 메뉴 | `LibraryChrome.tsx`의 라이브러리·책장·소스 고정 섹션, 모바일 드로어에도 탐색 요소 제공                                 | 접기 상태를 추가하고 데스크톱/모바일에서 같은 메뉴 의미를 유지                         |

| 소스 화면   | `SourceHubScreen.tsx`에 목록 표시 방식, 필터, 작품 상세, 회차·가져오기·다운로드 UI 존재                                | 전체 목록·상세·다운로드 경로를 재사용하고 중복 구현 방지                               |
| 조회 상태   | `useExternalSourceController.ts`가 단일 활성 소스와 목록 취소 컨트롤러를 관리                                          | 이 컨트롤러를 여러 홈 섹션이 동시에 조작하면 안 됨. 홈의 읽기 전용 조회 상태를 분리    |

| 온라인 표지 | remote/local 설치 소스 구현에 각각 64개 URL 캐시, 상한 도달 시 가장 먼저 삽입된 항목의 URL 해제                        | 캐시가 없는 상태는 아님. 용량·표시 중 참조·동시 요청 공유가 없는 부분을 개선           |
| 표지 조회   | 컨트롤러가 현재 목록의 모든 `coverRef`를 대상으로 최대 3개씩 조회                                                      | 여러 홈 섹션으로 확장하면 화면 밖 표지까지 요청하므로 화면 근처 우선순위 필요          |
| 콘텐츠 분류 | 소스에 `lang`, 문서/이미지 기반 `contentKind` 정보 존재                                                                | 이미지라는 이유만으로 만화와 웹툰을 정확히 자동 구분할 수 없음                         |

## 3. 정보 구조와 이름

### 3.1 주 탐색

주 진입점은 `라이브러리`와 `탐색`이다. 라이브러리는 보관·읽기, 탐색은 새 작품 찾기다. 설정의 `소스 관리`는 연결·설치·저장소·업데이트를 담당한다. 세 화면에 동일한 설치 관리 UI를 반복하지 않는다.

데스크톱 사이드 메뉴 예시:

```text
Moya
탐색                         ← 독립 진입점

⌄ 라이브러리
  전체 / 읽는 중 / 완독 / …
⌄ 책장                  관리
  내 책장 …
⌄ 소스                  관리
  고정한 소스 …
  모든 소스 보기
```

- 세 섹션은 **독립적으로** 접을 수 있다. 하나를 펼쳐도 다른 섹션은 유지한다.
- 처음에는 펼친 상태를 유지해 기존 동선을 보존한다. 접기 상태는 이 기기에 저장한다.
- 섹션 제목은 실제 버튼으로 만들고 `aria-expanded`, `aria-controls`, 키보드 포커스를 제공한다.
- 옆의 `관리` 버튼은 접기 버튼과 분리한다. 관리 아이콘을 눌렀는데 섹션까지 접히지 않아야 한다.
- 접힌 섹션 안에 현재 선택된 항목이 있으면 제목 옆에 간단한 선택 상태를 표시한다. 화면 이동마다 강제로 펼치지 않는다.
- 처음에는 기존 소스 바로가기를 보존한다. 사용자가 고정을 구성한 뒤에는 고정 소스 우선으로 정리하고 나머지는 `모든 소스 보기`로 접근한다.
- 모바일 메뉴에도 같은 섹션과 접기 기능을 적용한다. 좁은 화면에서는 라이브러리/탐색 간 전환을 드로어 밖의 간단한 상단 전환으로 제공한다. 이 작업만을 위해 고정 하단 내비게이션 전체를 재설계하지 않는다.

### 3.2 탐색의 내부 탭

`만화 / 소설 / 웹툰`은 추천 구성 예시이며 고정된 콘텐츠 타입이나 새 런타임이 아니다.

- 최초 진입은 사용 가능한 소스를 고르는 짧은 구성 화면으로 시작한다. `추천 구성 사용`으로 문서/이미지 기준 소스 선택을 제안하되 최종 배치는 사용자가 정한다.
- 웹툰은 자동 추정하지 않는다. 사용자가 탭을 추가하고 원하는 소스를 지정한다.
- 탭 추가·이름 변경·순서 변경·숨기기·삭제를 지원한다. 동일 소스를 여러 탭에 넣을 수 있다.
- 각 탭 안에서 소스 선택, 소스 순서, 목록 종류, 목록 제목, 표시 밀도를 설정한다.
- 예: `웹툰` 탭에 `A 소스 최신`, `A 소스 인기`, `B 소스 완결 작품`을 배치한다. 완결 목록은 B 소스가 해당 필터를 지원할 때만 가능하다.
- 기본 구성은 소스 하나당 주요 목록 1개로 간결하게 시작한다. 추가 목록은 사용자가 선택한다.
- 탭/목록 순서 변경은 드래그와 위·아래 이동 버튼을 함께 제공한다. 모바일 가로 탭 스크롤은 탭 전환 제스처와 충돌하지 않아야 한다.
- 구성 편집은 별도 `탐색 편집` 화면/시트에서 하고 `저장/취소`를 제공한다. 카드 탐색 중 실수로 순서가 바뀌지 않게 한다.
- 탭 삭제는 탐색 구성만 삭제한다. 설치된 소스·책장·다운로드·읽기 기록은 삭제하지 않는다. 삭제 결과에서 되돌리기를 제공한다.
- 설치 해제/비활성화된 소스를 구성에서 자동 삭제하지 않는다. `사용할 수 없는 소스`로 표시하고 다시 연결하거나 목록을 제거하게 한다.

## 4. 화면과 조작 경험

### 4.1 탭 홈

```text
탐색                         검색  편집
[만화] [소설] [웹툰]                   ← 사용자 탭

소스 A · 최신 업데이트          전체 보기 >
[표지] [표지] [표지] …
 작품명  작품명  작품명

소스 B · 인기                   전체 보기 >
[표지] [표지] [표지] …

소스 C · 완결 작품              전체 보기 >
이 소스에 연결할 수 없습니다.      다시 시도
```

- 홈은 가로 목록, 전체 보기는 반응형 그리드/목록을 기본으로 한다. 모바일은 다음 카드 일부가 보이게 해 가로 이동 가능성을 알리고 데스크톱은 명시적 이전/다음 버튼을 제공한다.
- 표지 영역 비율과 제목 두 줄 높이를 예약해 로딩으로 카드가 밀리지 않게 한다. 원본 표지는 기본적으로 잘라내지 않고 여백을 사용한다.
- 카드에는 제목·필요한 작가 정보·라이브러리 보유 상태를 우선 표시한다. 소스가 제공하지 않는 평점·연재 상태·최신 회차·순위를 만들어 표시하지 않는다.
- 목록 제목에 소스 이름을 항상 표시한다. 다른 소스의 결과를 모을 때에도 카드에서 출처를 식별할 수 있게 한다.
- 자동 재생 배너, 자동 가로 이동, 모든 섹션의 무한 스크롤은 넣지 않는다. 홈은 짧은 미리보기 목록과 전체 보기로 구분한다.
- 표지를 눌러 상세로 들어가는 동작이 기본이다. 작은 카드에 설치/다운로드/삭제 버튼을 모두 얹지 않는다. 필요한 부가 동작은 메뉴로 제공한다.
- 하나의 소스가 느려도 다른 목록은 먼저 표시한다. 홈 전체에 단일 로딩 덮개를 두지 않는다.

### 4.2 전체 보기·분류·검색

- `전체 보기`는 해당 소스·목록 모드·필터를 유지한 소스 화면으로 이동한다.
- 장르/완결/정렬 등은 기존 필터 정의로 생성한다. 소스마다 다른 분류를 하나의 가짜 공통 분류로 치환하지 않는다.
- 자주 쓰는 필터 조합을 `탐색에 추가`할 수 있게 한다. 이는 구성 프리셋이며 소스 사이트를 자동 순회하는 구독 작업이 아니다.
- 필터 적용 중 기존 목록을 유지하고 갱신 상태를 표시한다. 실패 시 기존 목록과 입력을 보존한다.
- 첫 제공 범위에서 현재 탭의 선택한 단일 소스 검색을 확실히 지원한다. 검색 범위를 항상 표시한다.
- 다음 단계에서 `이 탭의 모든 소스` 검색을 추가한다. 제출 시에만 실행하고 소스별로 결과/실패를 독립 표시한다. 검색어 입력마다 전체 소스에 요청하지 않는다.
- 통합 검색 결과는 소스별 묶음이다. 서로 다른 사이트의 인기순/관련도 점수는 합산하지 않는다. 제목이 같아도 다른 소스의 작품을 자동 병합하지 않는다.

### 4.3 상세·읽기로 이어지는 흐름

- 기존 상세·회차·다운로드·라이브러리 연결을 재사용한다. 카드에서 보던 표지도 상세 화면이 이어받아 재사용한다.
- 이미 보관한 작품에는 `읽기/이어보기`와 보유 상태를 제공한다. 현재 source/account/work 식별자로 기존 연결을 찾는다.
- 뒤로 가면 원래 탭, 목록 모드, 검색어, 필터, 로드한 페이지, 세로 위치와 가로 목록 위치를 복원한다.
- 목록이 만료되어 재조회하더라도 기존 카드부터 표시한다. 갱신 결과는 `새 목록 보기` 또는 명시적 새로고침으로 적용해 보고 있던 카드 순서를 바꾸지 않는다.
- 작품 삭제/권한 해제 등으로 위치를 복원할 수 없으면 가장 가까운 남은 항목으로 이동하고 간단히 안내한다.

### 4.4 빈 화면·실패·접근성

| 상태                  | 표시 및 행동                                                                |
| --------------------- | --------------------------------------------------------------------------- |
| 소스 없음             | `소스 추가` → 기존 소스 관리, 완료 후 탐색 구성으로 복귀                    |
| 탭에 소스 없음        | `소스 선택`, 다른 탭은 계속 사용 가능                                       |
| 정상 조회 0건         | `조건에 맞는 작품이 없습니다`, 필터 초기화                                  |
| 초기 조회 중          | 해당 목록 크기에 맞는 스켈레톤, 전체 화면 고정 금지                         |
| 캐시 있음 + 갱신 실패 | 기존 목록 + 마지막 조회 시각 + 다시 시도                                    |
| 인증 필요             | 해당 소스의 연결/인증으로 이동, 구성과 위치 유지                            |
| 미지원 기능           | 해당 기능 숨김 또는 편집 화면에서 이유 표시, 빈 인기 목록으로 위장하지 않음 |
| 외부 서버·TLS 오류    | 소스 단위 오류, 인증서 오류를 로그인 문제로 안내하지 않음                   |
| 표지 실패             | 크기 유지되는 기본 표지, 작품 상세 접근은 계속 가능                         |

터치 영역은 최소 44px를 목표로 한다. 키보드로 탭 이동·편집·카드 접근·목록 이동이 가능해야 한다. 상태를 색으로만 구분하지 않고, 모달/시트 종료 후 원래 조작 버튼에 포커스를 돌려준다. `prefers-reduced-motion`을 존중한다.

## 5. 소스 기능을 과장하지 않는 규칙

| 소스 기능/유형        | 탐색 처리                                                            |
| --------------------- | -------------------------------------------------------------------- |
| 인기 + 최신 제공      | 둘 다 구성 가능. 선택한 목록만 요청                                  |
| 인기만 제공           | 인기 제공, 최신을 인기 데이터로 대체하지 않음                        |
| 검색만 가능           | 검색 진입 카드. 목록을 만들기 위한 빈 검색/인기 호출을 강제하지 않음 |
| 필터 제공             | 해당 소스 필터 및 사용자 저장 목록 지원                              |
| 클라우드 폴더/파일    | 폴더 바로가기와 파일 탐색. 플랫폼 인기/최신 작품으로 취급하지 않음   |
| 지원 여부 미확인      | 확인 중/미확인과 미지원을 구분. 연결/선택 시 최소 조회로 확인        |
| 패키지 안의 여러 소스 | 패키지 단위가 아닌 개별 contribution/source ID로 선택                |

`latest`는 사이트에 따라 새로 등록된 작품이 아니라 최근 회차가 갱신된 작품일 수 있다. 의미가 확인되지 않은 경우 `최신 업데이트`로 안내하며 `신작`이라고 단정하지 않는다. `popular`도 해당 소스가 반환한 인기 목록이지 Moya 전체 순위가 아니다.

현재 `availableModes`는 browse 응답에 포함되므로 아직 조회하지 않은 소스의 기능을 모두 안다고 가정할 수 없다. 최초 선택/연결 때 얻은 기능 정보를 세션에 보관하고 확장/연결 변경 시 갱신한다. 필요하면 알려진 어댑터에 선택적 기능 메타데이터를 추가하되, 기존 확장을 일괄 변경해야 하는 새 필수 계약은 만들지 않는다.

## 6. 상태·조회·캐시 설계

### 6.1 최소 구조

권장 책임 분리이며 파일 이름은 구현 시 기존 관례에 맞춘다.

- `DiscoveryScreen`: 홈·탭·소스 목록 미리보기·편집 진입.
- 탐색 구성 저장소: 버전 있는 탭/소스/목록 배치 데이터.
- 탐색 조회 저장소: 기존 레지스트리를 통한 읽기 전용 조회, 요청 공유, 캐시와 구독.
- 표지 세션 캐시: 표지 수명과 동시 조회의 단일 소유자.
- 기존 `SourceHubScreen`/controller: 선택한 소스 전체 보기·상세·회차·다운로드.
- 기존 앱 내비게이션: 탐색 홈과 소스 상세 사이의 이동/복원 확장.

대형 `App.tsx`와 소스 컨트롤러에 홈 상태를 계속 추가하지 않는다. 하지만 범용 대시보드 프레임워크·플러그인 레이아웃 엔진·새 전역 상태 라이브러리를 만들 필요도 없다.

### 6.2 구성 저장

`schemaVersion`, 안정적인 탭 ID, 이름/순서/숨김, 목록 ID, 소스 ID, 모드, 선택적 필터 프리셋, 밀도가 최소 데이터다. 탭 이름을 식별자로 쓰지 않는다.

- 구성/접기 상태는 새로고침·재접속 후 유지한다. 목록 응답/표지 바이트와 분리한다.
- 우선 이 기기에 저장하고 서버 주소·로그인 사용자별로 구분한다. 로컬 모드는 별도 프로필 범위로 둔다.
- 현재 서버에 저장되는 데이터로 오인하지 않도록 편집 화면에 `이 기기의 탐색 구성`을 표시한다. 초기 범위에서 자동 기기 간 동기화를 약속하지 않는다.
- 기존 설정 구조를 활용한 구성 내보내기/가져오기는 후속 편의 기능으로 둔다. 계정 토큰·쿠키·표지 URL은 포함하지 않는다.
- 필터 정의가 확장 업데이트로 달라지면 프리셋을 검증한다. 유효하지 않은 필터를 임의로 다른 위치의 필터에 적용하지 않고 재설정을 요청한다.
- 계정/연결 변경은 캐시를 무효화한다. 재연결 가능한 소스 배치는 남기되 다른 사용자의 구성을 자동 재사용하지 않는다.

### 6.3 목록 캐시

탐색의 새 목록 캐시는 **브라우저 탭/앱 실행 세션 메모리**를 기본으로 한다. 기존 회차·가져오기용 영속 캐시는 별도 기능이므로 제거하거나 정책을 덮어쓰지 않는다.

키는 서버/사용자 범위 + 소스 ID + 연결 계정/세대 + 패키지 세대 + 모드 + 정규화된 검색/필터 + 페이지 커서다. 소스명이나 탭명으로 캐시를 구분하지 않으므로 동일 소스를 두 탭에 넣어도 요청을 재사용한다.

초기 정책 제안(측정 결과가 아닌 시작값):

- 최신 목록 5분, 인기 목록 15분, 검색 5분을 신선도 기준으로 한다.
- 세션에서 최대 100페이지 또는 직렬화 목록 데이터 약 8MiB 중 먼저 도달하는 한도로 미사용 항목을 정리한다.
- 만료 시 캐시부터 보여주고 해당 화면이 활성화될 때만 갱신한다. 숨긴 탭/모든 소스의 주기적 새로고침은 하지 않는다.
- 새로고침은 해당 탭에서 활성화된 목록으로 제한하고 같은 키의 진행 중 요청에 합류한다.
- 계정·권한·소스 세대 변경 후 과거 데이터는 표시하지 않는다. 일시적인 네트워크 실패에만 같은 범위의 캐시를 활용한다.
- 홈 미리보기는 소스의 첫 페이지에서 최대 12작품을 표시한다. 홈을 채우려고 여러 페이지를 자동 수집하지 않는다. 전체 보기에서 다음 페이지를 요청한다.

### 6.4 표지 캐시

목표는 **같은 세션에서 같은 표지를 다시 받을 필요를 줄이면서, 표시 중인 URL을 해제하지 않는 것**이다. 메모리 한도 초과로 이미 퇴출된 표지까지 재요청 0회를 보장하지는 않는다.

- 현재 remote/local의 64개 캐시를 감싸는 두 번째 캐시를 쌓지 않는다. 소유권을 공통 세션 캐시로 옮기거나 기존 캐시 자체를 공통 정책으로 바꾼다.
- 표지 키에 소스/계정/연결·패키지 세대/work 또는 coverRef/제공되는 표지 revision을 반영한다. 제목이나 변할 수 있는 URL 문자열만 사용하지 않는다.
- 캐시 적중 시 사용 순서를 갱신하는 LRU와 바이트 한도를 함께 둔다. 시작값은 Blob 32MiB / 200개 중 먼저 도달하는 한도다. 디코딩된 이미지와 DOM 메모리는 별개이므로 이 값이 전체 메모리 상한이라는 뜻은 아니다.
- 카드/상세에서 사용하는 표지는 참조를 유지한다. 사용 중에는 URL을 revoke하지 않고 마지막 참조 해제 후 퇴출 가능하게 한다. 일시적인 초과분은 미사용 항목으로 회수하고 선행 로딩을 줄인다.
- 같은 키의 진행 중 요청은 하나로 합친다. 카드 한 곳이 사라졌다고 다른 카드가 사용하는 요청까지 취소하지 않는다.
- 화면에 보이는 표지 → 가까운 다음 카드 순서로 요청한다. 먼 섹션의 표지는 미리 전부 가져오지 않는다. DOM에 `loading=lazy`만 추가해도 사전에 실행된 cover API 호출이 줄어드는 것은 아니다.
- Blob URL만이 아니라 소유권도 구분한다. 내장 커넥터가 제공한 일반 HTTPS URL은 revoke 대상이 아니며, 직접 URL 경로는 브라우저 HTTP 캐시의 제약을 명시한다. 세션 재사용이 필요한 경로는 기존 인증된 broker의 이미지 반환 방식에 맞춰 통합한다.
- 외부 사이트 이미지를 새 프런트엔드 직접 fetch 경로로 우회하지 않는다. 기존 인증·허용 도메인·TLS·응답 크기 제한을 보존한다.
- 실패한 표지는 짧은 유예(예: 30초) 후에만 재시도한다. 인증/차단/TLS 오류를 자동 재시도로 반복하지 않는다. 명시적인 재시도 및 인증 완료는 유예를 해제할 수 있다.
- 로그아웃/서버 변경/소스 제거/연결 세대 변경 시 관련 요청과 캐시를 무효화한다. 늦게 도착한 응답도 이전 세대이면 폐기한다.
- 세션 종료 시 객체 URL을 정리한다. 표지 Blob을 `localStorage`/`sessionStorage`/새 Service Worker 캐시에 저장하지 않는다.
- 라이브러리에 저장한 책의 영속 표지(`BookCover`/가져오기)는 이 정책과 별개로 유지한다.

### 6.5 요청량·화면 복원

- 선택한 탭의 화면 근처 목록부터 요청한다. 초기 진입에서 설치된 모든 소스를 호출하지 않는다.
- 시작값: 목록 요청 동시 2개, 표지 동시 4개. 동일 소스 조회는 우선 직렬화한다. 기존 서버/호스트 제한을 완화하지 않으며, 클라이언트 큐가 서버 제한을 대체하지 않는다.
- 대기 중인 화면 밖 요청은 취소/제거할 수 있지만, 공유 중인 요청은 소비자 수에 맞춰 처리한다. 모든 요청에는 본문 수신까지 포함하는 유한한 취소 기한을 적용한다.
- 탭 선택 시 즉시 캐시/스켈레톤을 표시한다. 다른 탭에서 늦게 온 결과가 현재 탭을 덮어쓰지 않게 한다.
- 앱 히스토리에 탐색 진입·전체 목록·작품 상세를 구분한다. 내부 탭/밀도 변경은 현재 화면 상태 교체를 기본으로 해 뒤로 가기를 불필요하게 늘리지 않는다.
- 복원은 안정적인 작품 키 + 카드 내부 상대 위치를 우선하고 픽셀 위치를 보조로 사용한다. 캐시가 퇴출된 경우 복원에 필요한 페이지를 제한적으로 다시 요청하고 무한히 이전 커서를 재생하지 않는다.
- 처음부터 모든 가로 목록에 복잡한 가상화를 넣지 않는다. 홈 미리보기 개수/화면 근처 로딩으로 제한하고, 전체 목록의 큰 데이터에서 필요성이 확인될 때 적용한다.

## 7. 구현 순서와 완료 기준

완료 체크는 구현과 해당 단계 확인 후에만 갱신한다. 각 단계는 별도 커밋과 짧은 결과 기록을 남긴다. 공통 계약 변경은 해당 소비자를 함께 수정하며 중간에 깨진 상태로 배포하지 않는다.

### D1 — 메뉴와 탐색 진입

- [ ] 세 메뉴 독립 접기, 기기 저장, 모바일/키보드 접근.
- [ ] 라이브러리/탐색 진입과 기존 소스 바로가기·관리 연결.
- [ ] 탐색 구성 모델과 탭 추가/이름/순서/숨김/삭제, 소스 선택.
- [ ] 최소 한 탭의 소스 목록과 기존 전체 보기/상세 왕복 연결.

완료 기준: 소스를 선택해 작품 상세를 열고 뒤로 돌아올 수 있으며, 기존 라이브러리·책장 동선과 상태가 보존된다. 비어 있는 정적 홈만 만들어 완료하지 않는다.

### D2 — 플랫폼형 홈과 세션 재사용

- [ ] 소스별 인기/최신 목록, 지원 여부 확인, 독립적인 로딩/오류 표시.
- [ ] 여러 목록을 동시에 조회할 읽기 전용 상태 및 요청 공유.
- [ ] 목록 캐시와 표지 단일 소유권·참조 유지·LRU·요청 우선순위.
- [ ] 탭/목록/상세 왕복 위치 복원, 늦은 응답 차단, 기존 보유 작품 표시.

완료 기준: 두 개 이상 소스를 둔 탭에서 한 소스가 느리거나 실패해도 다른 목록을 쓸 수 있다. 캐시 안의 표지는 탭 왕복 시 재사용되고 표시 중 해제되지 않는다. 이 단계부터 새 홈의 실제 사용성을 판단한다.

### D3 — 커스터마이징과 검색 완성

- [ ] 모드·목록 제목·소스/목록 순서·표시 밀도 편집 및 저장/취소.
- [ ] 소스 필터 프리셋 저장/탐색에 추가, 확장 변경 후 유효성 처리.
- [ ] 단일 소스 검색 범위 표시와 전체 목록 필터 UX 정리.
- [ ] 현재 탭의 여러 소스 검색, 소스별 결과/실패/다음 페이지 처리.
- [ ] 구성에서 없어진 소스 복구, 삭제 되돌리기, 모바일·키보드 사용 마무리.

완료 기준: 사용자가 직접 만든 만화/소설/웹툰 탭에 같은 소스를 중복 배치하고 각기 다른 필터로 사용할 수 있다. 검색과 상세 진입 후에도 구성이 바뀌지 않는다.

### D4 — 선택적 후속 개선

- [ ] 탐색 구성 내보내기/가져오기, 기존 동기화 모델과 연결 가능성 검토.
- [ ] 사용자가 고른 탭을 기본 진입 화면으로 설정.
- [ ] 소스별 제공 정보가 충분할 때 추가 배지·분류 바로가기.

D4는 핵심 탐색 기능 출시를 막는 조건이 아니다. 추천 알고리즘, 자동 전 소스 수집, 서버 통합 검색 인덱스, 배경 자동 다운로드, 자유 HTML/CSS 편집기, 모든 네이티브 앱 기능 복제는 이번 범위 밖이다.

## 8. 필요한 검증만 수행

문서 작성 단계에서 제품 테스트를 추가하지 않는다. 구현 때도 공통 로직의 중요한 실패 조건과 실제 화면 동선만 검증한다.

| 확인        | 최소 기준                                                                                            |
| ----------- | ---------------------------------------------------------------------------------------------------- |
| 반응형/조작 | 모바일 360/390px와 데스크톱에서 메뉴 접기·탭 편집·작품 상세 왕복, 키보드 접근                        |
| 캐시        | 같은 표지가 여러 목록/상세에 등장해도 진행 중 요청 1개, 왕복 재사용, 표시 중 URL 해제 없음           |
| 수명/격리   | 탭 A→B→A 빠른 이동, 계정/소스 세대 변경 중 응답, 퇴출 후 재조회                                      |
| 실패 격리   | 한 소스 시간 초과·인증 오류·표지 실패가 다른 목록을 막지 않음                                        |
| 실제 소스   | 사용자가 사용하는 문서/이미지 소스 각각으로 제공되는 인기·최신·필터를 확인. 미지원은 미지원으로 기록 |
| 상태 복원   | 상세→목록·검색→상세→뒤로 가기 시 같은 카드와 필터, 갱신 중 자동 순서 변경 없음                       |
| 구성        | 중복 소스 배치, 소스 제거/재설치, 필터 정의 변경, 접기 상태 재접속 유지                              |

실사이트 확인은 조회 위주로 제한하고 호출량을 기록한다. 실패 시 네트워크/외부 사이트와 Moya 기능 결함을 구분한다. 개발자 도구의 요청 수만으로 화면이 안정적이라고 결론 내리지 않고 실제 카드·표지·스크롤 위치를 함께 본다. 변경과 무관한 전 플랫폼 테스트 반복은 요구하지 않는다.

## 9. 착수 시 결정·기록할 항목

추가 사용자 답변 없이 위 기본안으로 시작할 수 있다. 다음 항목은 첫 구현에서 근거와 함께 기록한다.

1. PR #52 병합 후 기준 커밋과 제품에서 사용하는 내비게이션 상태 확장 지점.
2. 사용자 실제 소스들의 browse 기능 및 내장/설치 소스별 표지 소유권 차이.
3. 최초 추천 탭 구성과 모바일 주 전환 위치의 실제 화면 확인.
4. 캐시 상한·동시 요청 시작값으로 모바일 왕복이 안정적인지, 필요한 조정만 반영.
5. 단계별 완료 커밋, 실제 확인한 동작, 미지원/후속 항목. 검토/계획을 구현 완료로 표시하지 않음.
