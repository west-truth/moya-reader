# 설정 UI/UX 구현 검토

검토 대상: PR #52, `c31fb92`. 검토일: 2026-09-20.
결론: 핵심 기능은 들어갔으나 S0~~S5 전체 완료로 보기에는 결함과 누락이 있다. 현재 상태의 머지는 권하지 않는다.
아래 R1~~R7은 c31fb92 검토 당시 기록이다. 이후 수정 상태는 문서 마지막에 추가했다.

## 1. 수정이 필요한 결함

### R1 · P1 · 빠른 보기 하단 옵션이 잘리고 스크롤되지 않음 — 브라우저 재현

- 위치: `src/styles/reader-shell.css:486`, `:500`.
- 부모는 최대 높이와 `overflow: hidden`을 가지지만, 내부 콘텐츠 높이를 제한하는 flex/grid 배치가 없다.
  내부의 `overflow-y: auto`만으로는 스크롤 영역이 생기지 않는다.
- 실제 컴포넌트와 제품 CSS를 번들링한 Chrome 검사에서 390×844, 페이지 모드의 전체 설정 버튼 시작 좌표는
  약 895px로 화면 밖이었다. 휠 입력 후 내부 scrollTop은 계속 0이었다.
- 360×640에서는 읽기 방식·여백 등 더 많은 항목이 잘린다. 1366×768에서도 하단 버튼 일부가 잘렸다.
- 해결: 패널을 제한된 높이의 세로 flex/grid로 만들고 헤더를 제외한 콘텐츠에 `min-height: 0`과 스크롤을 준다.
  작은 높이와 가상 키보드가 열린 경우를 포함해 마지막 버튼까지 실제 접근 가능한지 확인한다.

### R2 · P1 · PR의 hosted-source CI 실패 — 원격 로그 확인

- 위치: `scripts/extensions/mangayomi-app-gate.ts:119`, `:209`.
- 새 이름은 콘텐츠 소스지만 Mangayomi 앱 검사는 계속 `/^익스텐션/` 탭을 기다린다.
- GitHub 실행 `35482346616`, hosted-source의 “Verify original Mangayomi install through comic reader”에서
  위 선택자를 찾다가 30초 timeout. browser-web와 windows-native-source는 통과했다.
- `scripts/reader-ui-smoke.mjs:800`, `:990`, `:1002`, `:1015`에도 사라진 “읽기 설정 열기” 버튼을 찾는 코드가
  남아 있다. 해당 스크립트는 이번 검토에서 실행하지 않았으나 선택자 이관은 함께 필요하다.
- 해결: 새 빠른 보기/전체 설정 동선을 검사에 반영하고 실패한 해당 gate만 재실행한다.

### R3 · P2 · 빠른 보기의 방향키가 본문 페이지 넘김에 전달됨 — 코드 경로 확인

- 위치: `src/features/reader/ReaderChrome.tsx:104`, `:444`, `src/features/reader/ReaderScreen.tsx:595`.
- 빠른 보기 open 상태는 ReaderChrome 안에만 있어 ReaderScreen의 overlay 차단 조건에 포함되지 않는다.
- 문서 단축키는 버튼에 포커스된 방향키/PageUp/PageDown에 대해서는 dialog 안의 대상도 허용한다.
  빠른 보기의 테마·닫기·± 버튼은 이 키를 자체 처리하지 않으므로 뒤쪽 본문이 넘겨지는 경로가 열린다.
- 손잡이의 방향키는 자체 preventDefault가 있어 이 경로와 다르다.
- 해결: 현재 활성 모달 내부의 키 입력을 본문 단축키에서 제외하거나 빠른 보기 상태를 리더 overlay에 연결한다.
  실제 ReaderScreen 전체에서의 별도 브라우저 재현은 아직 실행하지 않았다.

### R4 · P2 · 숫자를 비우면 최소값으로 자동 저장됨 — 브라우저 재현

- 위치: `src/features/reader-settings/SettingsSlider.tsx:99`.
- `Number('')`가 0이 되므로 입력을 지운 상태에서 다른 컨트롤을 누르면 0을 유효 숫자로 확정한다.
- 18px를 지우고 줄 간격 입력을 누르자 `onChange({ fontSize: 11 })`에 해당하는 값 변경이 발생했다.
- 해결: 빈 문자열과 유효하지 않은 입력은 기존 값으로 복원한다. 유효한 숫자의 범위 제한과는 별개로 처리한다.

### R5 · P2 · 새 슬라이더 손잡이가 접근성 트리에서 숨겨짐 — Chrome AX 확인

- 위치: `src/features/reader-settings/SettingsSlider.tsx:121`.
- 손잡이 버튼의 부모 트랙에 `aria-hidden=true`가 있어 `role=slider`와 값 정보가 접근성 트리에서 빠진다.
- Chrome Accessibility.getFullAXTree에서 보이는 슬라이더가 0개였다. 숫자 입력/± 버튼은 별도로 남아 있지만
  손잡이의 포커스와 스크린리더 슬라이더 조작 계약은 충족되지 않는다.
- 해결: 접근성 숨김을 장식용 트랙/채움 요소에만 적용하고 실제 손잡이는 노출한다.

### R6 · P2 · 모바일 메뉴가 계획과 다르고 뒤쪽 분류를 찾기 어려움 — 브라우저 재현

- 위치: `src/features/reader-settings/reader-settings-panel.css:2240`, `ReaderSettingsPanel.tsx:189`.
- 계획은 분류 목록 → 상세 → 뒤로였으나, 현재는 가로 탭 8개와 기존 상세 화면이다.
- 390px 화면에서 탭 영역은 약 374px, 전체 탭 폭은 약 661px였다. 다운로드·동기화·앱 정보는 처음에 화면 밖에
  있고 리더 보기/리더 조작 등 이름도 축약된다. 모바일에서는 저장 상태 안내도 숨겨진다.
- 해결: 계획한 모바일 목록/상세 탐색을 구현하고 뒤로·포커스 복귀를 연결한다. 데스크톱 왼쪽 분류는 유지한다.

### R7 · P2 · 오조작 방지 슬라이더가 만화·듣기 설정에 적용되지 않음 — 코드 확인

- 위치: `src/features/fixed-document/FixedDocumentScreen.tsx:3436`, `:3467`,
  `src/features/tts/TTSAddonPanel.tsx:632` 이후.
- 만화의 수동 자르기·밝기·대비·채도, 듣기의 속도·피치·볼륨 등은 여전히 native range의 즉시 onChange를 쓴다.
- 텍스트 설정의 공통 컨트롤만 바뀌어, 사용자가 제기한 트랙 오조작 문제가 다른 보기 설정에는 남는다.
- 해결: 값 설정용 range에 공통 컨트롤을 적용하되, 페이지 탐색/재생 탐색 range는 기존 동작을 보존한다.

- S4는 `ExternalSourceSettingsPanel`의 기본/플러그인 목록을 그대로 붙였다. 패키지 형식별 Mangayomi/APK/
  Suwayomi 버튼은 남았으며 계획한 사용 중/찾기/저장소/업데이트의 통합 구조는 아니다.
- 다운로드 공통 설정으로의 소스 화면 바로가기, 저장소 URL 복사 등도 계획 수준으로 남아 있다.
- 네 방향 여백, 전역 다운로드 집행, 자동 업데이트 스케줄러를 분리한 판단 자체는 타당할 수 있다.
  다만 이 항목들과 미구현 UI를 모두 S0~S5 완료 표시로 묶어서는 안 된다.
- 계획 문서의 “문서 작성만 한다”, “제품 코드 구현을 의미하지 않는다”와 상단 완료 표기가 동시에 남아 있다.
  구현된 항목/명시적 후속/아직 빠진 항목으로 완료 상태를 다시 적어야 한다.

## 3. 추가 UX 보완

- 빠른 보기에는 저장 중/실패/재시도 상태가 전달되지 않고 닫기는 로컬 open 상태만 바꾼다.
  기존 전체 설정의 `closePanel()`은 writer를 flush한다. 같은 저장기를 사용하는 점은 맞지만 종료·오류 UX까지
  같은 경로는 아니다. 즉시 종료와 저장 실패를 집중 확인할 필요가 있다.
- 좁은 화면에서 두 쪽을 선택하면 실제 한 쪽으로 표시될 수 있다는 설명이 빠른 보기에는 없다.
- 사용자 테마 이름 변경이 없고 동일 이름으로 저장하면 기존 테마를 알림 없이 덮어쓴다.
- 조작 탭에도 “이 책에만 적용”이 표시되지만 gesture 업데이트는 전역 설정 경로다. 기존 혼동을 새 분류에서도
  유지하고 있으므로 적용 범위를 정확히 표시해야 한다.
- 다운로드 설명은 모든 다운로드의 보장처럼 읽힌다. 회차 큐의 정책임을 밝혀야 하며 자동 받기처럼 별도 경로의
  중단 복구 보장과 서버에서 이미 실행 중인 요청의 취소 완료를 동일하게 표현해서는 안 된다.

## 4. 이번에 확인한 범위와 한계

- 기존 대규모 테스트는 반복하지 않았다. 코드/계획 대조, PR 실패 로그, 실제 React 컴포넌트와 제품 CSS의
  분리된 Chrome 화면 검사로 검토했다. 운영 데이터와 설치 상태는 변경하지 않았다.
- 크기: 390×844, 360×640, 1366×768. 실제 휴대폰 터치/관성 검사는 아니다.
- 정상 확인: 텍스트 슬라이더 트랙 탭은 값 불변, 드래그 중 값 저장 없음, 손잡이를 놓으면 한 번 반영됨.
- 재현: 하단 잘림/휠로 접근 불가, 빈 숫자 입력 최소값 저장, 접근성 트리 슬라이더 누락, 모바일 탭 밀림.
- 코드상 연결 확인: 새 조판 필드는 프로필 정규화, 실제 본문 CSS, 페이지 측정 캐시 키에 연결돼 있다.
  실제 장문 작품에서 새 옵션 변경 후 원문 anchor 유지까지 이번에 재검증한 것은 아니다.
- 재현 스크립트: `/tmp/moya-settings-review.mjs`, 결과: `/tmp/moya-settings-review-results.log`.
- 스크린샷: `/tmp/moya-review-quick-360.png`, `/tmp/moya-review-quick-390.png`,
  `/tmp/moya-review-settings-390.png`.

권장 순서: R1~R5와 실패 gate를 먼저 해결하고 R6/R7을 반영한다. 이후 S4 실제 UI 범위와 후속 항목을 정리하고,
모바일 빠른 보기에서 값 변경·닫기·다시 열기·페이지 위치 유지만 집중 검사한다.

## 5. 보완 결과

R1~R7을 수정하고 S4 검색·필터·즐겨찾기·통합 업데이트 검토를 추가했다. 빠른 보기 저장 상태/flush,
테마 이름 변경/덮어쓰기 확인, 조작 탭 전역 범위, 다운로드 정책 설명도 반영했다.

브라우저에서는 빠른 보기 마지막 버튼 접근과 모바일 목록/상세/뒤로/포커스를 확인했다. 이전 hosted-source
실패 지점인 Mangayomi 앱 gate는 로컬 재실행에서 통과했다. 변경 후 GitHub CI 결과는 PR에서 별도 확인한다.
세부 검증 및 남겨 둔 기능은 [구현 계획의 보완 기록](2026-09-20-settings-ux-plan.md#12-검토-후-보완-2026-09-20)을 참조한다.
