- [ ] 운영 반영 후 사용자 브라우저에서 체감 확인 — 이번 작업은 배포하지 않음

기존 탐색 세션 캐시는 유지한다. 새 라이브러리, 영구 이미지 저장소, 이미지 변환 파이프라인, 프록시 변경은 추가하지 않는다.

## 확인한 차이

2026-09-20 운영 컨테이너의 API에 읽기 요청만 수행했다. 목록·표지 조회 이외에 설치/설정/콘텐츠 상태를 변경하지 않았다.

| 서비스      | 소스        | 목록 첫 관측 / 재요청   | 표지 첫 관측 / 재요청 | 표지 크기  |
| ----------- | ----------- | ----------------------- | --------------------- | ---------- |
| Moya        | 네이버 웹툰 | 2,651 / 2,696ms (112개) | 1,591 / 1,439ms       | 52,310B    |
| Moya        | TOTAL 토끼  | 3,362 / 2,432ms (26개)  | 2,570 / 2,382ms       | 3,345,480B |

| total-tokki | 토탈토끼    | 662 / 29ms (49개)       | 397 / 17ms            | 176,708B   |

두 서비스는 목록 구성·정렬·선택 표지·연결 설정이 달라 동일 작업의 성능비로 해석할 수 없다. 최초 관측도 완전한 콜드 상태를 보장하지 않는다. 다만 Moya의 같은 표지 재요청이 원본 다운로드를 반복하는 것은 코드와 요청 양쪽에서 확인됐다.

로컬 참고: `/home/koho5155/Docker_Services/total-tokki/live-sources.mjs`의 `CACHE_TTL`·`imageCache`·`fetchRemoteImage`, `server.mjs`의 `/api/live/image`. tokki는 목록 2분, 이미지 24시간/최대 80MiB 캐시를 사용한다. Moya의 인증 경계와 명시적 새로고침 동작에 맞춰 다른 정책을 적용했으며 코드를 복사하지 않았다.

## 구현

- `services/apk-worker/source-cover-cache.mjs`: 계정별 카탈로그 인스턴스 메모리에만 표지 보관. 최대 32MiB/200개, 10분 만료, LRU 제거. 초과 크기 항목은 재사용 대상으로 저장하지 않는다.
- 키는 소스 ID + 패키지 digest/activation + 표지 URL 해시. 같은 URL이라도 계정·소스·확장 버전·소스 설정 세대가 다르면 공유하지 않는다. 변경된 표지 URL도 새로 받는다.
- MIME·크기·기존 이미지 계약 검증 후 Blob과 digest를 저장하고 요청별 asset handle은 매번 새로 만든다. 오류는 캐시하지 않는다. 본문 회차 이미지는 이 캐시에 넣지 않는다.
- 동시 표지 요청은 하나로 합친다. 일부 소비자 취소는 다른 소비자를 취소하지 않고, 전부 취소하거나 카탈로그를 닫으면 진행 중 캐시 채우기도 중단한다.
- 목록은 소스·세대·검색·필터·보기 방식·페이지가 같은 **진행 중 요청만** 병합한다. 후속 새로고침은 원본을 다시 요청한다. 서버 목록 TTL 캐시는 이번에 추가하지 않았다.
- 목록의 작품 참조 파일을 하나씩 기다리던 부분은 8개씩 저장한다. 저장 완료 후에만 목록을 반환하므로 바로 이어지는 표지/상세 요청에 필요한 참조가 보장된다.

기존 브라우저 목록 캐시(인기 15분/기타 5분) 및 표지 Blob 캐시는 그대로 사용한다. 서버 재시작 시 새 캐시는 비워진다. 일반 소스/사용자 제작 moyaext 전체의 서버 표지 경로까지 바꾼 것은 아니며, 이번 대상은 공통 호환 카탈로그를 쓰는 Mangayomi/APK다.

## 검증

- catalog / source-cover-cache / shared-task Node 검사 17개 통과. 용량·만료·LRU, 계정 인스턴스 격리, 취소, 잘못된 응답 복구, 세대 변경, 요청별 handle, 목록 새로고침·조건 분리를 확인했다.
- 실제 운영 표지 응답을 읽기 전용 API 브리지로 받아 **별도 임시 저장소의 수정 카탈로그**에 연결했다. 결과:
  - 네이버 표지 74,102B: 최초 2,684ms → 재사용 5ms, 운영 표지 요청 총 1회.
  - TOTAL 토끼 표지 3,345,480B: 최초 4,807ms → 재사용 18ms, 운영 표지 요청 총 1회.
- 이 수치는 수정 카탈로그 호출 시간이며 Docker 명령/API 브리지 비용을 포함한다. 새 버전이 배포된 브라우저의 종단 간 로딩 시간은 아니다. 임시 저장소는 검사 후 제거했다.

- 기존 extension-packages 라우트 검사 2개 통과. Mangayomi host 검사 6개 중 4개는 실행 제한 30초에서 통과했고, 2개는 테스트 내부 10초 signal이 만료됐다. 수정 전 `4393257`의 격리 worktree에서도 동일한 두 검사가 같은 10초 제한으로 실패함을 확인했다. 동일한 두 테스트의 임시 복사본에서 fixture signal만 30초로 늘려 재실행하자 2개 모두 통과했다. 임시 파일은 제거했으며 제품 제한과 저장소 테스트 파일은 변경하지 않았다. 변경 파일 ESLint·포맷·diff 검사도 통과했다.

## 남는 한계

- 첫 원본 목록·표지 요청은 소스/네트워크/프록시 응답에 의존한다. 이번 수정만으로 첫 화면 전체가 즉시 뜬다고 보장하지 않는다.
- 3.3MB 같은 큰 원본 표지는 처음 내려받는 비용과 브라우저 전송/디코딩 비용이 남는다. 썸네일 변환은 효과와 CPU·메모리 비용을 따로 확인한 뒤 필요하면 후속 작업으로 진행한다.
- 서버 목록 TTL 캐시를 추가하려면 사용자 새로고침이 캐시를 우회하는 계약도 함께 설계해야 한다. 이번에는 기존 최신성 동작을 유지했다.
