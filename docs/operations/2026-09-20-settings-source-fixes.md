# 설정·소스 업데이트·다운로드 정리

## 확인한 문제

- 모바일 `.modal header` 규칙이 내부 설명 헤더에도 sticky를 적용해 긴 설명이 스크롤을 가림.
- 소스 카드 즐겨찾기/탐색 버튼에 색상·테두리·여백이 없어 브라우저 기본 버튼으로 표시됨.
- 운영 웹 로그의 Mangayomi `inspect` 요청이 반복 422. 설치 요청 이전에 실패.
- 설치 목록을 읽기 전용 확인하고 공개 JS를 비교한 결과 토끼 소설 0.2.4, 11toon 0.1.9, TOTAL 토끼 0.1.8 등의 설치 digest와 현재 다운로드 파일이 동일. 목록에는 더 높은 버전이 있으나 inspect가 동일 digest를 일괄 거부함.

## 수정 범위

- 내부 설정 설명만 일반 스크롤 영역으로 복구. 대화상자 제목/닫기는 유지.
- 즐겨찾기는 소스 필터 기능을 유지하며 테마 색상·별 아이콘·눌림 상태를 적용. 작품 탐색 버튼도 동일한 스타일로 정리.
- 업데이트 목록은 이름/버전/저장소 호스트를 분리 표시. 동일 JS라도 저장소 버전이 높으면 명시적 검토 후 버전 정보를 갱신. 동일 버전·동일 파일과 다운그레이드는 계속 거부.
- 다운로드는 콘텐츠 소스의 하위 화면으로 이동. 독립 설정 탭 제거, 상위 화면 돌아가기 제공.

## 읽은 회차 보관 정책

- 기본 자동 정리 꺼짐. 기기·서버·계정 범위의 설정. 활성화는 사용자가 직접 선택.
- 보관 기준 5/10/20회. 명시적인 회차 읽음 기록만 집계하며 나중 회차로 건너뛴 것을 완독으로 추정하지 않음. 페이지 수가 아닌 회차 수로 계산.
- 최근 완료한 N회, 이어보기 위치의 회차, 읽지 않은 회차, 즐겨찾기 작품, 소스 연결 없는 직접 가져온 파일은 제외.
- 대상 미리보기와 수동 정리 확인 제공. 자동 모드는 리더를 나온 작품에 대해 한 번, 대기열이 쉬고 리더가 닫혔을 때 실행. 앱을 꺼둔 동안 실행하는 서버 예약 작업은 아님.
- 삭제 직전 읽음·보관 대상 재계산, 미리 본 대상과 교집합만 적용. 콘텐츠 리비전이나 계정이 달라졌으면 건너뜀. 기존 회차 삭제·자산 정리 경로 재사용.
- 서버 다운로드 삭제는 다른 기기에도 반영. 재다운로드 가능 여부는 원본 소스 상태에 따름을 UI에 표시.
- 모든 라이브러리의 백그라운드 주기 스캔, 새로운 삭제 저장소/스케줄러는 추가하지 않음.

## 검증

- 동일 JS의 0.2.4→0.2.7 설치·비활성 상태 보존·재열기 및 동일 버전/다운그레이드 거부 회귀 검사.
- 정확한 읽음 기준, 최근 회차/이어보기/즐겨찾기 보호, 기본 꺼짐, 미리보기 확인, 리더 종료/작업 중 대기, 오래된 리비전 제외 검사.
- 기존 TXT/만화의 실제 삭제·재다운로드 저장소 테스트와 기존 소스 컨트롤러 검사 재사용.
- 실제 설정 컴포넌트 + 전체 CSS를 이용해 모바일 설명 스크롤, 다크/라이트 버튼 테마, 다운로드 하위 이동 확인.
- 관련 단위·저장소·컨트롤러 검사 91개 통과. 최종 변경 후 정리 관련 6개 재검사 통과. 웹/서버 TypeScript, 변경 범위 ESLint, CSS/포맷 검사 통과.
- 설정 브라우저 검사 360/390/1366px 통과. 360px 다크/라이트 캡처에서 버튼 테마와 하위 메뉴 복귀, 설명 영역 여백도 확인.
- 운영 소스 설치와 운영 다운로드 삭제는 수행하지 않음. 배포는 별도.
