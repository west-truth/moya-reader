# 확장 소스 저장 한도와 표지 네트워크 검토

검토일: 2026-09-20. 실제 운영 소스를 읽기 전용으로 조사한 기록이며, 공개 문서에서는 콘텐츠 사이트명,
저장소 주소와 운영 환경 식별 정보를 생략한다. 운영 설치·설정·DNS·프록시·방화벽은 변경하지 않았다.

## 목록 실패: 실행 상태 저장 한도

- 운영 목록 요청은 HTTP 422였지만, 격리된 원본 확장의 `getPopular(1)`은 HTTP 200 응답을 받아 안내 카드를 포함한 26개 항목을 반환했다.
- SharedPreferences 변경 데이터는 150,299 bytes였다. 기존 `validatePreferenceChanges()`의 전체 JSON 48KiB 제한 때문에 화면에 결과를 전달하기 전에 `compatibility_preferences_invalid`가 발생했다.
- Mangayomi 확장은 SharedPreferences를 사용자 설정뿐 아니라 캐시에도 사용한다. 저장 한도만 늘리면 vault의 기존 64KiB 읽기 제한과 런타임 입출력 제한에서 다시 실패할 수 있다.

사용자 입력은 기존 48KiB/256키로 유지하고, 소스 실행 상태는 256KiB/2,048키로 따로 검증했다.
`mangayomi-options` vault에만 1MiB 암호화 파일 상한을 적용했다. 읽기·쓰기 한도를 맞추고,
초과 쓰기는 기존 파일을 교체하지 않는다. `source_storage_limit`로 구분하며 캐시를 임의로 삭제하지 않는다.

격리된 호스트에서 목록 26개 → 종료 → 암호화 저장소 재열기 → 목록 26개를 확인했다.
후속 호출의 상태는 137,958 bytes였다. 외부 상태는 시점에 따라 달라지며 이 검사가 모든 회차의 호환을 보장하지 않는다.

근거: [Mangayomi SharedPreferences 브리지](https://github.com/kodjodevf/mangayomi/blob/aaa0aaebe70cbdc42f67fee9f29992ecd5fc4777/lib/eval/javascript/preferences.dart),
`apps/server/src/extensions/mangayomi/preferences.ts`, `host.ts`, `source-credential-vault.ts`.

## 표지 네트워크 조사

휴대폰에서 직접 실행한 다른 앱과 Moya self-host는 요청 경로가 다르다.
Moya 확장 요청은 휴대폰 → Moya API → 원본/CDN으로 진행하므로, 휴대폰의 DNS 설정을 바꿔도 서버의 DNS는 바뀌지 않는다.

- 일반 DNS와 암호화 DNS로 받은 서로 다른 CDN 주소에 원래 TLS 호스트 이름을 유지해 연결했으나 둘 다 `CERT_HAS_EXPIRED`였다. 확인한 인증서 만료일은 2026-09-17 20:44:51 UTC였다.
- 별도 표지에서는 두 DNS 방식이 같은 주소를 반환했고 직접 연결은 `ECONNRESET`이었다. 임시 로컬 SOCKS 프록시 비교에서 첫 요청은 실패했지만 후속 요청은 WebP 704,176 bytes를 반환했다.
- 이후 목록이 다른 호스트의 표지를 반환했을 때는 직접 연결도 성공했다. 모든 표지 실패를 DNS나 프록시 부재로 설명할 수 없다.
- 격리된 `source.getCover`에서는 WebP 704,176 bytes와 JPEG 185,067 bytes를 자산으로 반환했다. 임시 설치·저장소·프록시는 종료 후 정리했다.

인증서 검증 해제는 하지 않았다. 인증서 만료, 연결 재설정, 앱별 요청 경로는 따로 진단해야 한다.
이번 관측만으로 네트워크 장비의 원인이나 다른 앱과의 동일한 실행 환경을 입증하지는 못한다.

`pinnedProxyAgent()`는 승인된 IP로 연결하고 TLS 호스트 이름을 유지한다. 프록시 사용 시에도 목적지 DNS는
Moya 서버가 담당하므로, 필요하면 서버 resolver를 별도로 검토한다.

## 기본 프록시 사용 방법 / 적용 범위

1. **설정 → 콘텐츠 소스 → 소스 연결 · 기본 프록시**에서 서버가 접근 가능한 HTTP/HTTPS/SOCKS5 주소를 저장한다.
2. 기존 개별 프록시가 없는 소스는 기본값을 자동 사용한다. 기존 개별 주소는 그대로 우선 적용한다.
3. 각 패키지의 **확장 옵션 → 소스 연결 방식**에서 `기본값 사용 / 직접 연결 / 개별 프록시`를 고른다. `직접 연결`은 기본 프록시가 있어도 우회한다. `개별 프록시`는 주소 입력이 필수다. 예전 주소는 모드를 바꿔도 보관하므로 다시 선택할 수 있다.
4. 기본 주소를 비워 저장하면 전역 직접 연결이다. **서버 기본값 복원**은 운영자의 `SOURCE_OUTBOUND_PROXY`로 돌아가며, 환경변수가 없으면 직접 연결한다.

적용 대상은 이 Moya 서버에서 실행하는 Mangayomi JS와 `.moyaext`다. 목록/표지/회차 이미지/브라우저 요청과 SDK 로그인 확인에 적용하며, 해당 형식의 저장소 조회·업데이트 파일 다운로드는 소스별 예외와 별개로 전역 기본값을 사용한다. 별도 Suwayomi 서버, APK Java 실행기, 브라우저 자체 요청, 외부 콘텐츠 생성 서비스의 내부 통신에는 이 기본값을 강제로 적용하지 않는다. 설치 패키지의 옵션 선언이 없어도 `.moyaext` 소스별 호스트 연결 옵션은 표시된다.

설정은 사용자별 기존 서버 vault에 저장되어 서버 재시작과 다른 클라이언트에서도 유지된다. 로컬 UI만 바꾸거나 서버 환경 파일을 덮어쓰지 않는다. 인증된 `GET/PUT /api/source-network-settings`로 관리하고 revision 충돌은 HTTP 409로 거부한다. 저장 후 시작되는 요청부터 적용하며 진행 중 요청과 이미 받은 표지 캐시는 유지한다. 서버 vault 정책에 따라 일반 설정 동기화/내보내기에는 프록시 설정을 복사하지 않는다.

프록시는 별도 서비스다. UI에 주소를 입력하는 것만으로 ByeDPI가 설치되지는 않는다. Docker 배포 시 API와 같은 네트워크의 프록시 서비스 이름(예: `socks5://source-proxy:1080`)을 사용한다. API 컨테이너에서 `127.0.0.1`은 호스트의 임시 프록시를 가리키지 않는다. 이번 작업은 운영용 프록시 서비스 설치, 운영 기본값 지정, DoH resolver 전환을 수행하지 않았다.

검증: 캐시/호스트/기본값·예외 선택/API 충돌/SDK 브로커/설치 UI·클라이언트 관련 9개 파일 33개 테스트 통과. 전체 App 브라우저 검사에서 모바일 기본 프록시 저장, 유효하지 않은 주소 거부, 직접 연결 전환, 기존 설치·업데이트·탐색 흐름을 통과했고 page error는 0이었다. 운영 컨테이너를 다시 빌드하거나 배포하지 않았다.

웹/서버/스크립트 TypeScript, 변경 범위 ESLint, CSS 검사와 `git diff --check`도 통과했다. 새 의존성 설치나 전 플랫폼 테스트 재실행은 하지 않았다.
