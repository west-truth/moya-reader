# PR 검사 범위와 중복 정리

## 문제와 조치

PR #57의 `hosted-source` 실패는 `PaginatedReaderViewport.test.tsx`의 가짜 DOM에 `replaceChildren()`이 없어 발생했다. 페이지 블라인드 기능에서 이 DOM API를 사용하게 되었는데 테스트 환경 갱신을 놓쳤다. 실제 브라우저 검사는 통과했지만 기존 페이지 뷰어 회귀 검사를 로컬에서 빠뜨린 문제도 있었다. 가짜 DOM을 수정하고 해당 테스트를 유지한다.

기존 Quality는 Linux의 여러 Vitest 호출에서 **196개 파일을 총 221회** 실행했다. 웹 루트 타입 검사도 `check:web-local`, `typecheck`, `build`를 통해 반복했다. 웹 UI 수정에도 Windows Rust 전체 검사와 Docker Compose 전체 이미지 빌드/E2E를 항상 실행했다.

이번 변경은 검사 파일 삭제가 아니라 중복 제거와 무거운 검사 실행 범위 조정이다.

- `scripts/ci/quality-tests.mjs`: 기존 로컬 테스트 스크립트 7개와 워크플로의 추가 검사 목록을 합쳐 Vitest를 한 번 실행한다. 기존 196개 파일을 모두 유지한다. Node 테스트 기반 확장 runtime/SDK/CLI 검사는 별도로 유지한다.
- 루트 TypeScript 검사는 `hosted-source`에서 한 번 실행한다. 이후 루트 번들은 Vite로 빌드한다. 별도 엔트리/설정을 갖는 `apps/web`의 타입 검사와 빌드·산출물 검증은 유지한다.
- `scripts/ci/quality-scope.mjs`: PR 전체 변경 파일을 merge base 기준으로 확인한다. 삭제·이름 변경도 판정에 포함한다. 최근 커밋 한 개만 보지 않는다.
- 같은 PR에 새 커밋이 오면 이전 실행을 취소한다. `main` 실행은 자동 취소하지 않는다.

## 실행 기준

| 검사                                                        | PR                                             | main push / 수동 실행 |
| ----------------------------------------------------------- | ---------------------------------------------- | --------------------- |
| lint·타입·계약·라이선스·기존 단위/통합 검사·production 번들 | 코드 변경 시 한 번                             | 전체                  |
| 기본 웹 앱 브라우저 검사                                    | 웹 코드 변경                                   | 전체                  |
| 설정·탐색·리더 브라우저 검사                                | 해당 기능 또는 공유 UI/상태 변경               | 전체                  |
| Mangayomi 앱 브라우저 검사                                  | 확장/소스/관련 서버 경로 또는 공유 UI 변경     | 전체                  |
| APK 캐시, 텍스트 소스 companion                             | 해당 서비스/확장 변경                          | 전체                  |
| Windows Rust·native·mobile readiness                        | native 코드 변경                               | 전체                  |
| Docker Compose 전체 이미지 빌드·가져오기 E2E                | Docker/Compose·서버 엔트리/DB/빌드·서비스 변경 | 전체                  |

공통 패키지, 의존성/빌드 설정, CI 자체, 분류되지 않은 경로가 바뀌면 보수적으로 **전체 검사**를 선택한다. 따라서 이 CI 수정 PR 자체는 전체 실행으로 연결을 확인한다. 문서만 바꾸면 범위 판정 작업만 실행한다.

서버의 일반 비즈니스 로직 변경은 production 번들 검사와 단위/통합 검사로 검증하고, 전체 Docker E2E는 위 조건 및 main에서 실행한다. 실제 배포 전에는 해당 main의 배포 검사 결과를 확인한다. 소스별 모든 실사이트 요청이나 실기기 검증을 대체하는 구성은 아니다.

## 유지보수와 확인

- 로컬 전체 검사 명령 `check:web-server`, `check:web-local` 등은 그대로 사용할 수 있다. CI에서는 중복을 피하기 위해 개별 단계를 호출한다.
- 기존 테스트 묶음에 새 테스트를 추가하면 통합 CI도 같은 목록을 사용한다. 새로운 별도 테스트 묶음/브라우저 검사를 도입할 때는 통합 실행 목록과 범위 판정을 함께 갱신한다.
- `node scripts/ci/quality-tests.mjs --list`로 CI의 Vitest 대상 파일을 확인한다.
- `node --test scripts/ci/quality-scope.test.mjs`는 UI 단독 변경, 문서, 공유 코드, native, 배포, 알 수 없는 경로/전체 실행의 선택을 검증한다.
- 기존 CI 목록과 통합 목록의 집합 비교 결과: 누락 0개, 추가 0개, 중복 실행 25회 제거.
- PR #57에서 실패한 페이지 뷰어 테스트 2개는 수정 후 통과했다. 전체 통합 실행과 GitHub 결과는 PR의 최신 checks에서 확인한다.

단축 시간은 변경 종류와 runner 캐시에 따라 달라지므로 일정 비율로 보장하지 않는다. 검사 자체가 중요한 상태 복원·저장·권한·다운로드 회귀를 보호하는지 확인하지 않고 일괄 삭제하지 않는다.
