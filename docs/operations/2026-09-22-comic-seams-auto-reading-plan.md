# 만화 이미지 경계선과 자동 읽기 개선 계획

작성: 2026-09-22. 상태: **코드 검토 완료, 구현 전**.

이번 요청은 검토와 계획만 작성한다. 제품 코드·배포는 변경하지 않는다. 이미지 경계선은 원인을 확인한 뒤 작은 수정으로 해결할 수 있을 때 진행하고, 자동 읽기와 별도로 판단한다.

## 1. 현재 상태와 결론

| 항목                     | 확인한 현재 동작                                                                      | 제안                                                                   |
| ------------------------ | ------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| 만화 경계 없는 세로 보기 | 이미지 간 padding과 그림자를 제거하고, 회차 내 페이지 틀을 일반 문서 흐름에 유지한다. | 원본 선과 렌더링 경계를 먼저 구분한다. 기존 위치 보존 구조는 유지한다. |
| 만화 자동 스크롤         | 고정 문서 뷰어에 자동 읽기 연결이 없다.                                               | 일반·경계 없는 세로 보기 모두 일정 속도 스크롤을 추가한다.             |
| 만화 자동 넘기기         | 수동 단일 페이지·펼침 이동이 있다.                                                    | 현재 읽기 순서에 따라 일정 시간마다 다음 페이지/펼침으로 이동한다.     |
| 텍스트 자동 읽기         | 픽셀·줄·화면 스크롤, 블라인드, RSVP가 있다. 페이지 모드에서는 블라인드만 허용한다.    | 페이지 모드에 가림막 없는 시간 간격 자동 넘기기를 추가한다.            |

자동 읽기는 기존 이동·읽기 위치 저장을 재사용할 수 있어 구현할 만하다. 이미지 경계선은 스크린샷만으로 제거 가능 여부를 확정할 수 없다. 사진의 가는 가로선이 페이지 경계와 일치하는지도 실제 화면에서 확인해야 한다.

## 2. 이미지 사이 선: 확인과 수정 순서

### 코드에서 확인한 점

- `FixedDocumentScreen.tsx`의 `stableComicFlow`는 경계 없는 이미지 아카이브에 적용된다. `ComicPageFlow`가 페이지 틀을 유지하고 높이 변경 전후 읽던 위치를 보정한다.
- 이 경로는 `article` 높이를 `estimateContinuousPageSize()`로 지정하고, 내부 이미지는 같은 폭에 `height: auto`를 사용한다. 소수점 높이와 실제 이미지 경계가 일치하는지 확인할 필요가 있다.
- `fixed-document.css`에서 해당 모드의 padding은 0, opacity는 1, 이미지 그림자는 없다. 일반 이미지에 있는 그림자를 단순 제거하는 수정으로는 해결되지 않는다.
- 가상 배치 경로에는 `gap: -1` 보정이 이미 있지만, 현재 경계 없는 만화의 일반 흐름 경로에는 적용되지 않는다. 이 값을 바꿔도 해당 화면을 고치는 것이 아니다.
- 공통 이미지 스타일에 transform, clip-path, filter가 있다. 회전·자르기·색 보정을 껐을 때도 남는 기본 효과가 선에 관여하는지는 아직 검증하지 않았다.
- 과거 브라우저 검사는 스크롤 위치·페이지 유지 검증이다. 1px 안팎의 선이 없다는 시각 검증은 아니다.

### 구현 전에 할 최소 진단

1. 문제 회차의 인접 원본 이미지 두 장을 확인한다. 각각의 끝/시작 픽셀에 선이 있는지와 화면의 선 위치가 실제 이미지 경계인지 비교한다. 원본이 없으면 합성 이미지로 렌더링 문제까지만 확인했다고 기록한다.
2. 같은 연속 그림을 두 조각으로 나눈 합성 이미지를 실제 뷰어에 표시한다. 모바일 폭·데스크톱 폭, 대표 DPR 1/2/3에서 경계의 이미지/틀 좌표와 스크린샷을 비교한다. 확대·자르기를 끈 기본 상태부터 본다.
3. 틀과 이미지 높이 차이, 불필요한 기본 transform/filter/clip-path, 원본 선을 각각 구분한다. 설정을 전부 바꾸는 실험 대신 의심 항목만 한 번씩 비교한다.

### 원인별 처리

- **틀과 이미지의 높이 차이:** 로드된 페이지는 이미지와 틀이 동일한 폭·비율 기준을 쓰도록 정리한다. 미로딩 틀의 예상 높이와 기존 앵커 보정은 보존한다. 각 페이지 높이를 무조건 올림하는 방식은 회차 전체 오차가 누적될 수 있어 피한다.
- **기본 시각 효과의 경계:** 효과를 실제로 사용하지 않는 기본 상태에 한해서 불필요한 효과를 제거하는 작은 CSS 수정부터 비교한다. 사용자 회전·자르기·색 보정은 유지한다.
- **이미지 자체에 들어 있는 선:** 기본 화면에서 자동으로 잘라내지 않는다. 원본 그림/글자가 손실될 수 있으므로 이번 범위에서는 보류한다.
- **브라우저 합성 단계의 틈:** 앞의 조치로 해결되지 않고 재현된 경우에만 제한적인 경계 보정을 검토한다. 전 페이지에 큰 음수 여백을 적용하거나 캔버스로 통째로 합치지 않는다. 기존 스크롤 안정성과 메모리 사용을 해치면 이 수정은 보류한다.

완료 기준: 합성 연속 이미지에서 경계가 사라지고, 지연 이미지 도착·위로 스크롤·회차 이동에서 위치가 튀지 않아야 한다. 실제 사용자 원본 검증 여부는 따로 기록한다.

## 3. 사용자 경험

리더 메뉴의 명칭을 **자동 읽기**로 통일하고, 현재 보기 방식에서 사용할 수 있는 항목을 보여준다.

| 화면                    | 기본 제공 방식              | 조절                                          |
| ----------------------- | --------------------------- | --------------------------------------------- |
| 만화 세로 보기          | 자동 스크롤                 | 느리게/빠르게, 기존 1~12단계 체계 우선 재사용 |
| 만화 페이지·펼침 보기   | 자동 넘기기                 | `10초마다`처럼 실제 간격 표시                 |
| 텍스트 페이지·펼침 보기 | 자동 넘기기 + 기존 블라인드 | 넘김 간격, 블라인드 기존 속도                 |
| 텍스트 스크롤 보기      | 기존 자동 읽기 방식         | 기존 설정 유지                                |

- 페이지 간격 초안은 3~120초, 만화 기본 10초·텍스트 기본 20초로 둔다. 초 단위 숫자와 ± 조절을 제공한다. 기존 스크롤 모드의 `화면 단위 스크롤`과 페이지 모드의 `자동 넘기기`를 구분한다.
- 속도 조절은 기존 설정용 숫자 조절 UI를 재사용한다. 바를 잘못 눌러 값이 바뀌는 문제를 새로 만들지 않는다.
- 시작하면 설정창은 닫고 작은 정지 버튼만 표시한다. 중앙 가림막이나 큰 진행 패널·매초 바뀌는 카운트다운은 추가하지 않는다. 모바일 하단 탐색 바와 겹치지 않게 배치한다.
- 화면 탭·드래그·휠·키 입력, 설정/목차/검색 열기, 보기 모드 변경, 백그라운드 전환 시 멈춘다. 전경으로 돌아와도 자동 재시작하지 않는다.
- 스크롤 속도와 넘김 간격만 기기에 기억한다. 책을 다시 열 때 실행 상태는 복원하지 않는다.
- `다음 회차도 계속`은 기본 꺼짐. 켠 경우 기존 회차 이동 경로로만 이어간다. 준비되지 않은 회차를 연쇄 다운로드하는 별도 기능은 추가하지 않는다.
- 이미지/본문 로딩 중에는 기다린다. 실패하면 멈추고 기존 페이지의 재시도 UI를 쓴다. 기다린 시간을 몰아서 여러 페이지를 넘기지 않는다.

## 4. 구현 연결

### 텍스트 페이지 자동 넘기기

- `use-auto-scroll.ts`의 시작/정지, 입력 중단, 백그라운드 중단, 회차 전환 보호를 재사용한다. 현재 `modeAllowed`의 페이지 모드 제한을 새 방식에 맞게 확장한다.
- `auto-reading-modes.ts`의 기존 `page`는 스크롤 화면 이동이다. 의미를 바꾸지 않고 별도 `page-turn` 방식으로 구분해 저장된 설정을 보존한다.
- `PaginatedReaderViewport.tsx`의 기존 인접 페이지 준비, `autoTurning`, `commitPage`, 세대/취소 확인을 재사용한다. 블라인드 표시 없이 다음 경계로 이동하고, 펼침이면 현재 두 페이지 다음으로 이동한다.
- 타이머는 **현재 페이지가 준비된 뒤** 시작한다. 다음 페이지 준비가 늦으면 한 번만 대기하며, 실제 표시가 완료된 시점부터 새 간격을 센다. 넘김 요청이 중첩되지 않게 한다.
- 블라인드 동작과 TTS 충돌 방지는 그대로 유지한다.

### 만화 자동 스크롤·넘기기

- `FixedDocumentScreen.tsx`의 `viewportRef`, `turnPage(1)`, `goToPage`, 회차 경계를 연결한다. RTL에서도 논리적 다음 페이지를 사용하고, 펼침에서는 기존 spread 이동을 따른다.
- 기존 자동 읽기 훅에서 시작/정지·시간 처리에 필요한 작은 인터페이스만 분리해 재사용한다. 만화에 텍스트 `ReaderViewportApi` 전체를 구현하거나 새로운 범용 읽기 엔진을 만들지 않는다.
- 세로 스크롤은 requestAnimationFrame의 경과 시간으로 이동하며 긴 프레임 지연은 버린다. 픽셀 누적을 유지해 저속에서도 일정하게 움직이게 한다. 매 프레임 React 상태 갱신이나 전체 이미지 목록 탐색은 하지 않는다.
- 현재 화면과 곧 진입할 이미지가 준비됐는지 가까운 페이지 범위로 확인한다. 페이지 넘김은 현재 펼침의 이미지가 실제 로드된 후 시간을 세며, 다음 대상도 준비된 뒤 전환한다. `img.complete`만으로 성공을 판단하지 않고 오류/유효한 크기도 확인한다.
- 기존 근접 이미지 로딩 범위를 활용한다. 필요하더라도 다음 페이지/펼침까지만 준비하고, 한 회차 전체 디코딩이나 캐시 정책 확대는 하지 않는다.
- 세로 보기의 회차 경계에서 휠/터치 제스처 전용 다음 회차 처리와 자동 읽기가 동시에 실행되지 않게 연결한다. 다음 회차 옵션이 꺼져 있으면 경계에서 멈춘다.
- 첫 범위는 이미지 아카이브 만화와 텍스트 리더다. PDF 자동 읽기는 렌더 준비 조건이 달라 이번 필수 범위에서 제외한다.

## 5. 작업 순서와 필요한 검증

1. **경계선 원인 확인 → 가능한 작은 수정.** 해결이 불확실하면 결과만 기록하고 자동 읽기 작업을 막지 않는다.
2. **텍스트 페이지 자동 넘기기.** 기존 자동 읽기 훅·페이지 준비 경로를 활용하고 설정 UI를 정리한다.
3. **만화 자동 스크롤·자동 넘기기.** 동일한 정지 규칙과 작은 조작 UI를 연결한다.
4. **필요한 검사만 실행하고 결과 기록.** 각 완료 단위로 커밋한다.

최소 회귀 범위:

- 타이머: 준비 전 이동 없음, 간격당 한 번, 대기 후 몰아 넘김 없음, 입력/숨김/모드 변경 중단, 늦은 비동기 응답 무시.
- 페이지 이동: 텍스트 단일/펼침, 만화 단일/펼침/RTL, 마지막 페이지와 다음 회차 옵션.
- 브라우저: 모바일·데스크톱에서 조작부 겹침 없음, 느린 이미지 로딩 중 빈 페이지를 지나가지 않음, 실패 후 수동 재시도 가능.
- 경계선 수정 시에만 기존 만화 위치 유지 브라우저 검사와 경계 스크린샷 비교를 추가한다.

기존 자동 읽기 단위 검사와 리더 브라우저 fixture를 확장한다. 전체 플랫폼 테스트나 대용량 업로드 벤치마크는 이 작업 때문에 다시 실행하지 않는다.

## 6. 이번 검토의 한계

이번에는 코드와 첨부 스크린샷을 검토했다. 해당 회차의 원본 이미지 비교나 경계선 브라우저 재현은 아직 하지 않았으며, 원인을 확정하지 않았다. 자동 읽기 기능은 위 경로의 재사용 가능성을 확인한 단계이며 구현 완료나 실제 동작 검증으로 표시하지 않는다.

## 실행 기록 — 이미지 경계선

- 합성 단색 이미지를 실제 만화 뷰어로 표시해 모바일 393px에서 DPR 1/2/3 모두 어두운 경계 픽셀을 재현했다. DOM 이미지 좌표의 간격은 0이었다.
- transform/filter/clip-path를 각각 제거해 비교했다. `clip-path: inset(0)`만 제거해도 경계가 사라졌다. 기본 자르기 없음, 수동 자르기 0, 자동 자르기 미검출에는 `clip-path: none`을 쓰도록 수정했다. 실제 자르기 값은 보존한다.
- 수정 후 모바일 393px·데스크톱 1366px, DPR 1/2/3의 경계 픽셀이 연속 단색으로 유지됐다. 사용자 회차 원본은 검사하지 않았으므로 원본 자체의 선 제거를 보장하는 결과는 아니다.
- 기존 위치 유지 브라우저 검사는 자동 읽기 구현 후 관련 검사와 함께 한 번 실행한다.
