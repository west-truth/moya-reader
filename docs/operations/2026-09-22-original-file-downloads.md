# 대용량 원본 개별 다운로드

기준: `939e333` 이후. 운영 서비스는 변경하지 않고 별도 브랜치에서 구현한다.

아래는 `a649523`의 1차 구현 기록이다. 이후 같은 브랜치에서 전체 원본 ZIP 및 대용량 앱 백업·복원까지
[후속 구현](2026-09-22-large-backup-plan.md)으로 확장했다. 아래의 512MiB/1,000항목 제한은 당시 상태다.

## 범위

- Self-host 웹의 기존 `원본 다운로드`에서 로컬 합본의 원본 파일을 순서대로 보여 주고 개별 저장한다.
- 일반 단일 원본도 같은 서버 다운로드를 이용한다. 소스 전용 컨테이너를 CBZ 등으로 재구성하는 기존 내보내기와 네이티브/로컬 저장은 유지한다.
- 파일은 S3 → API 스트림 → 브라우저 다운로드로 전송한다. 프런트엔드의 `fetch().blob()`, 재압축, 임시 대용량 복사 없이 저장한다.
- 계정 인증을 거친 요청만 짧게 유효한 일회용 다운로드 주소를 발급받는다. 주소는 특정 작품/원본에 고정하며 만료·재사용·다른 원본 요청은 거절한다. 서버 내부 주소/계정 토큰은 반환하지 않는다.
- 전체 합본 ZIP, 앱 백업/복원 상한, Cloud Vault 지원 확대는 별도다. 이 화면에는 `파일별로 저장합니다. 읽기 기록은 포함되지 않습니다.`만 짧게 안내한다.

## 작업과 검증

- [x] 원본 목록·권한 확인·일회용 스트리밍 전송 구현.
- [x] 기존 다운로드 진입점에 모바일/PC 공통 원본 선택 화면 연결.
- [x] 인증/소유권/만료/재사용/변경된 원본 검사, 큰 스트림 취소 및 파일 내용 확인.
- [x] 관련 UI/전송 검사, 웹·서버 타입 검사, 변경 파일 lint/format. 전체 플랫폼 검사는 반복하지 않음.
- [x] 결과와 한계 기록. 이 문서를 구현과 함께 `feat/original-file-downloads`에 커밋한다.

## 구현 결과

- 라이브러리의 기존 `원본 다운로드`를 누르면 파일명·용량과 개별 저장 버튼을 표시한다. 긴 파일명은 줄바꿈하고, 30개 단위로 더 표시한다.
- 로컬 합본은 원본 `source_part` 자산을 회차 순서로 조회한다. 파일 내용을 읽거나 합본을 재압축하지 않는다. 기존 내부 컨테이너 형식은 기존 내보내기로 연결한다.
- 인증한 API 요청으로 60초 유효한 일회용 주소를 발급한다. 브라우저가 주소를 열면 현재 소유권·삭제 여부·원본 해시를 다시 확인하고 S3 스트림을 보낸다. 클라이언트 취소 시 스트림을 종료한다.
- Nginx에서도 다운로드 응답 버퍼링을 끈다. 다운로드 진행·취소는 브라우저 다운로드 관리자가 담당하며, Moya는 요청 시작만 안내한다.
- DB 마이그레이션과 새 운영 설정은 필요 없다. 운영 서비스는 변경하지 않았다.

## 검증 결과

- 관련 6개 파일의 18개 테스트 통과: 다운로드 인증·주소 만료/재사용·삭제/교체, UI 오류/재시도/닫기, 기존 합본 내보내기와 라우트 등록 포함.
- 513MiB 합성 스트림을 실제 로컬 HTTP로 전송하여 전체 크기와 SHA-256 일치를 확인했다. S3 입력은 모의 스트림이므로 실운영 저장소나 수 GB 실파일의 종단 검증 결과는 아니다.
- 독립 Docker 컨테이너의 Chromium에서 320/390/1366px 화면을 확인했다. 한글 파일명, 작은 실제 첨부파일 다운로드와 내용 일치, 긴 이름의 화면 넘침 방지, 더 보기 및 닫기 통과. 운영 볼륨/네트워크는 사용하지 않았다.
- 웹·서버 타입 검사, 변경 파일 ESLint/Prettier, CSS 및 계약 경계 검사, Nginx 설정 검사 통과. 전체 플랫폼 테스트는 실행하지 않았다.
- 새 테스트는 기존 CI 선별 목록에만 추가했다. 브라우저 검사는 `scripts/performance/original-files-smoke.mjs` 수동 실행으로 제공하며 새 CI 작업을 추가하지 않았다.

## 남는 제한

- 신규 개별 다운로드는 전체 파일을 메모리에 보관하는 500MiB 합본 내보내기 상한을 거치지 않는다. 기존 업로드·저장 용량 제한까지 바꾸지는 않는다.
- 전체 작품을 한 ZIP으로 재구성하는 내보내기, 앱 백업의 512MiB/1,000개 상한, Cloud Vault 합본 지원은 이번 범위가 아니다. 읽기 기록·메모 복원용 백업과 원본 저장은 다르다.
- 일회용 주소는 현재 API 프로세스에 보관한다. 재시작 시 사용 전 주소가 만료되며, 여러 API 인스턴스 사이의 공유는 지원하지 않는다.
- Range 이어받기는 지원하지 않는다. 다운로드가 끊겼거나 주소가 만료되면 원본 목록에서 다시 눌러 새 다운로드를 시작한다. 목록을 닫은 뒤에도 이미 시작된 브라우저 다운로드는 계속된다.
- 실제 운영 환경의 저장소·역방향 프록시를 거치는 수 GB 다운로드 속도와 모바일 브라우저별 장시간 백그라운드 동작은 배포 후 확인할 항목이다.
