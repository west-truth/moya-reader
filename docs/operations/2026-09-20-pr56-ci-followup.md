# PR #56 CI 후속 수정

## 확인한 실패

GitHub Actions `35505441690`의 `hosted-source`에서 `useExternalSourceController.test.tsx` 6개가 실패했다. 브라우저와 Windows 작업은 성공했다. 동일한 6개 실패를 로컬에서도 재현했다.

- 캐시 우선 조회가 추가됐지만 기존 검사는 캐시 조회 횟수가 0이라고 가정했다.
- 재시도는 원본 재확인을 위해 `cacheMode: reload`를 전달하지만 기존 검사는 이전 요청과 완전히 같다고 가정했다.
- 기존 검사는 권한 오류와 분류되지 않은 오류에도 캐시를 표시해야 한다고 가정했다. 현재 정책은 일시적인 네트워크 실패에 한해서만 캐시를 유지한다.

앞선 로컬 집중 검사에서는 이 기존 컨트롤러 파일을 빠뜨렸다. 테스트를 비활성화하거나 제한 시간을 늘리지 않고 현재 정책에 맞게 실패·취소·재시도 검사를 수정했다. 네트워크 전 캐시 조회와 네트워크 실패 후 캐시 조회가 늦게 끝나는 경우를 각각 검증한다.

## 실제 오류 처리 보완

텍스트 서버 오류를 사용자용 문구로 바꾸는 과정에서 HTTP 상태/오류 코드가 사라져, 502 등의 일시적 실패도 캐시 정책이 인식하지 못했다.

- `TextServerRequestError`에 상태와 제한된 오류 코드만 보존한다. 원본 본문·인증 정보·네트워크 원인 객체는 전달하지 않는다.
- 502/혼잡/시간 초과/연결 실패는 캐시 재사용 대상으로 분류한다.
- 인증·권한·확인 절차·잘못된 설정/응답·목록 세대 변경 등은 502/503으로 감싸져 있어도 캐시로 숨기지 않는다.
- 캐시를 사용할 수 없는 실패에서도 알림은 로컬 안내 문구를 사용한다. 원격 오류 원문이 알림으로 나가지 않는다.

## 병합 기준

#55가 squash 병합됐으므로 최신 main을 병합하고 #56의 기준을 main으로 변경한다. 병합 과정의 탐색 UI 충돌은 #55의 내용이 이미 포함됐음을 비교한 뒤 #56의 후속 구현을 보존해 해소했다. 이 기준 병합 자체의 파일 변경은 없다.

집중 검사 119개(소스 컨트롤러·페이지 추가·실제 텍스트 클라이언트 응답·캐시 정책), 변경 파일 lint/포맷 검사를 통과했다. 전체 검증은 수정 커밋의 CI에서 이어서 확인한다. 운영 배포는 포함하지 않는다.
