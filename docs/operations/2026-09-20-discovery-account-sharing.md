# 탐색 홈의 계정별 공유

## 목적과 범위

같은 Moya 서버의 같은 계정으로 접속하면 탐색 탭 구성이 기기마다 동일하게 보이도록 한다. 별도의 동기화 옵션은 추가하지 않는다.

- 공유: 탭 이름·순서·숨김·밀도, 소스 고정, 인기/최신 목록, 저장한 목록의 분류·필터.
- 기기별 유지: 현재 선택한 탭, 임시 검색·필터, 스크롤·더 불러온 페이지, 목록·표지 캐시. 리더 글자 크기 등 기존 기기 설정도 영향 없음.
- 로컬 모드는 기존 브라우저 저장 방식을 유지한다. 서로 다른 서버 또는 서로 다른 계정 사이의 공유는 하지 않는다.

## 구현

- `reader_settings.settings._moyaDiscovery`에 구성과 서버 발급 revision/updatedAt을 저장한다. DB 스키마 변경 없음.
- 인증된 계정의 `GET/PUT /api/discovery-settings`를 사용한다. 일반 `/api/settings` 응답에는 이 문서를 섞지 않는다.
- PUT은 expectedRevision을 확인하는 원자적 갱신이다. 동시에 저장하면 한쪽만 성공하고 다른 쪽은 409를 받는다. 기존 리더/연동 설정 갱신은 탐색 문서를 보존한다.
- 공유 문서는 허용한 구성·필터 필드만 재구성한다. 최대 30개 탭, 탭당 60개 목록, 전체 512KiB. 임시 질의나 캐시를 포함하지 않는다.

## 기존 구성과 첫 접속

1. 브라우저에 남아 있는 구성/서버 캐시로 즉시 화면을 표시하면서 서버를 조회한다.
2. 서버 구성이 있으면 그것을 사용한다. 새 기기의 자동 생성 기본 탭은 업로드하지 않는다.
3. 서버 구성이 없고 기존에 저장한 로컬 구성이 있으면 revision 0으로 한 번 가져온다. 두 기기가 동시에 가져오면 먼저 성공한 구성을 공유한다.
4. 기존 로컬 키는 백업으로 남기고 서버 구성 캐시는 별도 키에 쓴다. 다른 기기의 기존 로컬 구성을 임의로 합치지 않는다.

구성은 앱 시작, 탐색 진입, 탐색 화면으로 포커스/네트워크 복귀 시 조회한다. 탐색 화면을 보고 있을 때는 60초마다 확인하며 숨겨진 창에서는 주기 조회를 생략한다. 실시간 푸시 동기화는 아니다.

## 실패와 충돌 UX

- 저장 완료 응답을 받은 뒤에만 편집 창을 닫는다. 저장 중 중복 조작을 막고 실패하면 입력한 내용을 유지한다.
- 편집을 시작한 뒤 다른 기기 구성을 받았거나 서버 revision이 달라졌으면 오래된 편집을 덮어쓰지 않는다. 최신 구성을 확인하고 다시 편집하도록 짧게 안내한다.
- 연결 실패 시 마지막 구성으로 탐색할 수 있다. 서버 구성을 아직 읽지 못한 상태에서는 수정 내용을 서버에 덮어쓰지 않는다.
- 저장 응답 유실도 실제 서버에는 반영됐을 수 있으므로 다음 저장 전에 서버를 다시 읽는다.
- 요청마다 본문 수신까지 포함한 15초 취소 신호를 사용한다. 계정/서버가 바뀌거나 컨트롤러가 해제되면 이전 요청은 취소하고 늦은 결과를 무시한다.
- 소스 연결이 기기에서 사용 불가한 경우에도 공유 탭을 삭제하지 않고 기존 연결 안내를 사용한다.

## 검증

관련 검사 19개 통과(탐색·설정 17개, PostgreSQL/라우트 등록 2개). 후속 UI 보완 후 저장 관련 7개를 다시 확인했다. 390/1366px 브라우저 검사, 웹/서버 타입 검사, 변경 파일 lint, CSS/포맷 및 공유 계약 경계 검사 통과.

- 두 기기 저장소를 사용한 공유·기존 구성 가져오기·동시 가져오기·오래된 편집 충돌·오프라인·계정 해제 검사.
- 실제 PostgreSQL의 별도 임시 컨테이너/스키마에서 동시 저장 CAS, 계정 분리, 일반 리더/연동 설정 갱신 시 보존 검사. 운영 DB 사용 없음.
- 편집 UI의 비동기 저장 실패 시 초안 유지/확인 후 닫기 검사.
- 기존 탐색 브라우저 시나리오: 390/1366px에서 고정·필터·펼치기·페이지 추가·재진입. 외부 사이트나 운영 계정에 실제 구성을 쓰는 검사는 하지 않는다.

이 변경은 웹과 API를 함께 업데이트해야 한다. 구버전 API를 쓰면 동기화 실패가 표시되며 로컬 캐시로 읽기는 가능하다. 운영 배포는 이번 작업에 포함하지 않는다.
