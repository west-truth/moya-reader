# 작품 보기 방식 통일

## 범위와 결과

라이브러리, 탐색 홈, 개별 확장 소스의 작품 목록에 같은 네 가지 보기를 제공한다.

| 보기        | 표시                              |
| ----------- | --------------------------------- |
| 표지        | 기본 표지와 제목                  |
| 작은 표지   | 작은 표지, 두 줄 제목. 모바일 3열 |
| 목록        | 작은 표지와 작품 정보             |
| 텍스트 목록 | 표지 없이 제목과 작품 정보        |

- 공통 `WorkViewControl`에서 선택한다. 모바일 라이브러리는 기존 정렬 및 보기 메뉴에 배치한다.
- 회차 목록과 파일 소스의 파일 목록은 기존 구조를 유지한다.
- 탐색의 다중 소스 구분, 펼쳐보기, 검색·필터, 더 불러오기를 유지한다. 단일 소스 탭과 빠른 이동으로 연 소스에도 적용한다.
- 라이브러리 가상화는 작은 표지의 열 수를 실제 CSS에서 측정하며, 목록과 텍스트 목록은 한 행씩 처리한다.
- 표지 대신 텍스트로 표시할 때도 선택 표시, 읽기·추가·다운로드 작업 및 가져오기 상태를 유지한다.

## 저장과 이미지 요청

- 레이아웃은 기기별 브라우저 저장소에 보관한다. 서버의 탐색 탭 구성에는 새 필드를 추가하지 않는다.
- 라이브러리는 기존 `moya.library-view.v1`을 확장한다.
- 탐색은 탭별로 기억한다. 빠른 이동의 임시 소스는 해당 소스별로 기억한다.
- 개별 소스 화면은 기존 소스 보기 저장 키를 재사용하며, 모든 개별 소스 화면이 하나의 보기 선택을 공유한다. 기존 `list`는 유지하고, `cards`·`covers`는 기본 표지 보기로 전환한다.
- 탐색 편집의 표시 밀도 선택은 상단 보기 메뉴로 대체한다. 기존 밀도 값은 기기에 새 선택이 없을 때 기본값으로만 사용하므로 기존 설정 데이터는 보존된다.
- 텍스트 목록에서는 표지 컴포넌트를 마운트하지 않는다. 탐색 표지 요청·재시도는 취소하고, 개별 소스 컨트롤러도 작품 목록의 표지를 요청하지 않는다.
- 작품 상세 표지, 명시적으로 가져오는 작품의 표지 저장, 본문 이미지와 파일 소스는 이 표시 설정과 독립적이다. 보기 변경으로 기존 캐시를 삭제하지 않는다.

## 검증

- 관련 5개 테스트 파일 138개 통과: 새 보기의 작품 열기/작업 버튼, 기기 설정 복원, 텍스트 보기의 표지 요청 생략 및 전환 시 취소 포함.
- 웹 타입 검사, 변경 파일 ESLint, CSS 검사, 포맷 및 diff 검사.
- 실제 컴포넌트와 스타일을 묶은 임시 Chromium 화면에서 390px/1366px, 라이브러리·탐색 홈·개별 소스의 네 가지 보기를 확인. 가로 넘침 및 페이지 실행 오류 없음.
- 단일 소스 탐색 탭도 두 해상도의 네 가지 보기와 새로고침 후 복원을 확인.
- 라이브러리 1,000권의 각 보기에서 마지막 작품 접근 확인. 탐색·소스 보기 새로고침 후 복원 확인.
- 밝은 테마/어두운 테마 화면과 긴 제목, 소스의 라이브러리 추가 버튼을 확인. PC 목록 작업 버튼 넘침도 수정.
- 이 검사는 합성 작품 데이터를 사용한 UI 검증이다. 운영 데이터 변경이나 Docker 서비스 배포는 수행하지 않았다.

새로운 전체 테스트 묶음이나 CI 작업은 추가하지 않았다.
